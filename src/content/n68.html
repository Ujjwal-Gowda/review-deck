1. Why This Model Exists: The Browser GUI Constraint

In 1995, Brendan Eich designed JavaScript for Netscape Navigator under a strict design constraint: the user interface must never freeze, and programmers must not face multi-threaded deadlock bugs. If scripts manipulated DOM tree elements using preemptive threads (like Java or C++), developers would encounter continuous race conditions where Thread A removed a button while Thread B attempted to style it.

To eliminate deadlocks while remaining responsive, JavaScript adopted a single-threaded, non-blocking, event-driven runtime model with run-to-completion semantics. Concurrency is achieved not through parallel CPU threads, but through asynchronous event notification queues coordinated by an event loop.

3. Execution Order: Tracing Synchronous vs Microtask vs Macrotask

Consider this classic interview drill. Can you predict the exact console output sequence before looking at the explanation?

console.log("1: Synchronous");

setTimeout(() => {
  console.log("2: Macrotask (Timer)");
}, 0);

Promise.resolve().then(() => {
  console.log("3: Microtask 1");
}).then(() => {
  console.log("4: Microtask 2");
});

queueMicrotask(() => {
  console.log("5: Microtask 3");
});

console.log("6: Synchronous End");

Step-by-Step State Execution Trace

  1. console.log("1: Synchronous") executes immediately on the Call Stack. Output: 1: Synchronous.
  2. setTimeout(..., 0) requests the host environment (timer thread) to schedule a callback. When the 0ms delay elapses, the callback is pushed into the Macrotask Queue.
  3. Promise.resolve().then(...) resolves immediately; its .then callback is pushed into the Microtask Queue.
  4. queueMicrotask(...) pushes another callback directly into the Microtask Queue.
  5. console.log("6: Synchronous End") executes on the Call Stack. Output: 6: Synchronous End.
  6. Call Stack is now empty! The Event Loop immediately checks the Microtask Queue:
    • Dequeues and runs Microtask 1. Output: 3: Microtask 1. This returns a new Promise, scheduling Microtask 2.
    • Dequeues and runs Microtask 3. Output: 5: Microtask 3.
    • Dequeues and runs Microtask 2. Output: 4: Microtask 2.
  7. Microtask Queue is now empty! The Event Loop takes the first item from the Macrotask Queue:
    • Dequeues and runs Timer callback. Output: 2: Macrotask (Timer).

Final Output: 1, 6, 3, 5, 4, 2

4. The Four Rules of this Binding

In JavaScript, this is not bound to the function when it is declared. this is determined strictly by how the function is invoked at call time.

  1. Default Binding: Standalone function call fn(). In strict mode ("use strict"), this is undefined. In non-strict mode, it falls back to window (browser) or global (Node).
  2. Implicit Binding: Method call on an object: obj.method(). this is bound to obj.
    The Detached Method Trap 
    const user = {
  name: "Sarah",
  greet() { console.log(`Hello, ${this.name}`); }
};
const fn = user.greet;
fn(); // TypeError: Cannot read properties of undefined (reading 'name')
// Why? 'fn' is called without an object context, triggering Default Binding!
  3. Explicit Binding: Using .call(context, ...args), .apply(context, [args]), or .bind(context) to hard-bind the receiver.
  4. new Binding: When calling new Constructor(), JavaScript creates a fresh blank object, sets its prototype link, binds this to that new instance, and returns it.

Arrow Functions: Lexical this

Arrow functions (() => {}) do not have their own this binding. They resolve this lexically from their enclosing scope at declaration time, exactly like a normal variable in the scope chain. call(), apply(), and bind() cannot alter an arrow function's this.

class OrderService {
  constructor(taxRate) {
    this.taxRate = taxRate;
  }
  // Arrow method: permanently preserves 'this' when passed as a callback
  calculateTotal = (items) => {
    return items.reduce((sum, item) => sum + item.price * (1 + this.taxRate), 0);
  };
}

5. Prototypes & The Prototype Chain

JavaScript does not use classical class-based inheritance; it uses differential prototypical inheritance:

  • Every JavaScript object has an internal hidden reference called [[Prototype]] (accessible via Object.getPrototypeOf(obj)).
  • When you access obj.property, the engine first searches obj's own keys. If not found, it traverses up the prototype link: obj → Class.prototype → Object.prototype → null.
  • The ES6 class keyword is syntactic sugar over this prototype chain; methods declared inside a class body are placed directly on Class.prototype to conserve memory.
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  return `${this.name} makes a noise.`;
};

const dog = new Animal("Rex");
console.log(dog.speak()); // "Rex makes a noise."
console.log(Object.getPrototypeOf(dog) === Animal.prototype); // true
console.log(Object.getPrototypeOf(Animal.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype)); // null (end of chain)

6. Production Asynchronous Patterns

Modern JavaScript production applications rely on structured asynchronous coordination:

PatternAPIFailure BehaviorPrimary Use Case
Fail-Fast ParallelPromise.all([p1, p2])Rejects immediately if ANY promise rejectsAtomic transactions where all dependencies are mandatory.
Resilient Multi-FetchPromise.allSettled([p1, p2])Never rejects; returns status arrayDashboard aggregations where partial data is acceptable.
Fastest WinsPromise.race([p1, timeout])Settles on the fastest outcomeNetwork request timeout guards.
Request CancellationAbortController + signalThrows AbortError on abortCanceling in-flight HTTP requests when component unmounts.
// Resilient request with explicit timeout cancellation
async function fetchWithTimeout(url, timeoutMs = 5000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeoutMs);

  try {
    const response = await fetch(url, { signal: controller.signal });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (err) {
    if (err.name === "AbortError") {
      throw new Error(`Request timed out after ${timeoutMs}ms`);
    }
    throw err;
  } finally {
    clearTimeout(timer); // Prevent timer leak
  }
}

68.2 intermediate Fix this callback loop: why does it print "3, 3, 3" instead of "0, 1, 2"?
// Broken: 'var' has function scope, shared across all iterations
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 10);
}

// Fix 1: Use block-scoped 'let' (creates a fresh binding per iteration)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 10);
}

// Fix 2: Create a closure / IIFE passing i as a parameter
for (var i = 0; i < 3; i++) {
  ((capturedIndex) => {
    setTimeout(() => console.log(capturedIndex), 10);
  })(i);
}
