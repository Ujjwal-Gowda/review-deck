Serving content from servers close to users, and taking load off your origin.

user in Bengaluru → nearest edge PoP (Chennai) ──hit──► cached response in ~10 ms └─miss─► origin (your server / S3 in Mumbai) → cached at the edge for next time
  • What to cache: static assets with hashed filenames (Cache-Control: public, max-age=31536000, immutable), images, public pages (short TTL). Never cache per-user responses publicly (Cache-Control: private).
  • Cache key: by default the URL. Extra query params, cookies or headers in the key fragment the cache, so strip what doesn't matter.
  • Invalidation/purge: changing filenames (hashes) beats purging. Purge by URL or tag for HTML.
  • stale-while-revalidate: serve slightly stale content instantly while refreshing in the background.
  • Edge features: TLS termination, HTTP/3, compression, image resizing, WAF/DDoS protection, and edge functions (Cloudflare Workers, Netlify Edge).

Netlify, Vercel and Cloudflare Pages put your static sites (like the FreshOn demos) behind a CDN automatically; that's why they load fast worldwide. Check hits and misses with the x-cache, cf-cache-status or age headers (curl -I).
