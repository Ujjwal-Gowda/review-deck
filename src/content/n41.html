A README template that works

# Project name: one sentence on what it does and for whom
## Quick start       (copy-pasteable commands: clone → install → run, in under 5 minutes)
## Configuration     (env vars table: name, purpose, default, required?)
## Development       (tests, lint, project layout in 5 lines)
## Deployment        (or a link to it)
## Architecture      (a 1-paragraph overview + a diagram, or a link)

Go (go doc, pkg.go.dev), Rust (cargo doc --open), Python (docstrings, help()) and TS (TSDoc in the IDE) all generate browsable docs from these comments.

Comments: the rules

  • Explain why, not what. i += 1 # increment i is noise. # Razorpay rounds down to whole paise; match it or reconciliation fails is gold.
  • If you need a comment to explain what the code does, first try a better name or extracting a function.
  • Outdated docs are worse than none. Keep docs next to the code and update them in the same PR.

Practice

41.1 basic Write a README for your printer-doctor app using the template. Then follow it on a fresh clone and fix every step that fails.

The steps that fail on a fresh clone (a missing dependency, an undocumented env var, a wrong path) are documentation bugs. Commit the fixes in the same PR as the code they describe.
