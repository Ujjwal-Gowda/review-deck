How modern CPUs actually run code, and the code patterns that help or hurt.

  • Caches rule: an L1 hit costs ~1 ns, main memory ~100 ns. Sequential, contiguous access (arrays, struct-of-arrays) lets the prefetcher hide that latency. Pointer-chasing doesn't (chapter 3, chapter 5).
  • Branch prediction: the CPU guesses branches in order to keep its pipeline full, and a wrong guess costs about 15–20 cycles. Unpredictable branches in hot loops (random data) are slow; sorted data, or branchless code (x = cond * a + (1-cond) * b), helps.
  • SIMD: one instruction processes 4–16 values. Compilers auto-vectorise simple loops over arrays at -O2/-O3. NumPy, Rust iterators and C loops benefit; boxed objects in Python don't.
  • Instruction-level parallelism: independent operations run simultaneously; long dependency chains serialise them.
  • False sharing and contention between cores (chapter 27).
perf stat -e cycles,instructions,cache-misses,branch-misses ./app   # instructions per cycle, miss rates

This level matters for hot inner loops (parsers, image and video processing, game engines, databases), not for typical web handlers, which are dominated by I/O.

Practice

187.1 basic Sum a large array in C twice: first in order, then in random index order. Explain the timing difference with perf stat.

Random order causes far more cache misses (cache-misses in perf stat) and is several times slower, even though the number of additions is identical.
