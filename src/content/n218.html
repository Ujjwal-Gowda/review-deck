Getting machine-readable output you can trust your code to parse.

from pydantic import BaseModel, Field
class Complaint(BaseModel):
    category: str = Field(description="one of: late, damaged, missing, quality, other")
    severity: int = Field(ge=1, le=5)
    order_id: str | None
    summary: str

# Option A: tool/JSON-schema constrained output (the provider enforces the schema)

  • Prefer schema-enforced modes (forced tool use, "structured outputs" / JSON-schema response formats, grammar-constrained decoding for local models) over "please reply in JSON".
  • Validate with Pydantic or zod. On failure, repair: send the validation error back and ask for a corrected object (limit this to 1–2 attempts).
  • Design schemas for the model: clear field descriptions, enums instead of free text, optional fields for things that may be missing (otherwise the model invents values), and a reasoning field placed before the answer fields if you want it to think first.
  • Test on messy real inputs (Hinglish emails, empty messages), and track the parse-failure rate.
