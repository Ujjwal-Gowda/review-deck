Seeing, controlling and debugging running programs from the shell. The concepts are in chapter 4.

ps aux --sort=-%mem | head          # top memory users (RSS column = real RAM, in KB)
pgrep -a node                        # find by name (-a shows the full command)
htop                                 # interactive: F6 sort, F9 kill, F5 tree view
top -o %CPU                          # always available
kill 1234        # SIGTERM: ask nicely  → kill -9 1234 only if it ignores that
pkill -x firefox # by EXACT name. Careful: pkill -f matches full command lines, including your own shell's!
kill -STOP 1234; kill -CONT 1234     # pause / resume
nice -n 10 make -j12                 # start at low priority (19 lowest, -20 highest)
renice 15 -p 1234                    # lower an already running process
lsof -p 1234                         # files and sockets it has open
lsof -i :5170                        # WHO is using port 5170?
strace -f -e trace=openat -p 1234    # watch its system calls live

Reading memory correctly

free -h: look at available, not "free". Linux uses spare RAM as disk cache (buff/cache) and gives it back instantly when programs need it. RSS (resident memory) counts shared libraries in every process, so summing RSS overestimates real use. Swap use plus a sluggish system means RAM is genuinely short. vmstat 1 columns si/so show swapping happening live.

Process states (the STAT column)

R running, S sleeping (waiting for an event, normal), D uninterruptible sleep (stuck on disk I/O; a failing HDD produces lots of these), Z zombie (finished but not yet collected by its parent), T stopped.

53.1 basic Find which process holds port 5170, then stop it gracefully.

lsof -i :5170 (or ss -ltnp | grep 5170) gives the PID; then kill PID. Only use -9 if it's still there after a few seconds.
