Modelling "things" (an Order with items, a status and behaviour) in each language: records, methods, interfaces and variants.

A record with behaviour

@dataclass
class Order:
    id: int
    items: list[Item]
    status: str = "placed"
    def total(self) -> int: return sum(i.qty * i.price for i in self.items)
interface Order { id: number; items: Item[]; status: Status }
const total = (o: Order) => o.items.reduce((s, i) => s + i.qty * i.price, 0);   // data + functions (idiomatic)
class OrderModel { constructor(public id: number, public items: Item[]) {} total() { /* … */ } } // or a class
type Order struct { ID int; Items []Item; Status Status }
func (o Order) Total() int { t := 0; for _, i := range o.Items { t += i.Qty * i.Price }; return t }
struct Order { id: u64, items: Vec<Item>, status: Status }
impl Order { fn total(&self) -> u64 { self.items.iter().map(|i| i.qty * i.price).sum() } }
typedef struct { int id; Item *items; size_t n_items; Status status; } Order;
long order_total(const Order *o) { long t = 0; for (size_t i = 0; i < o->n_items; i++) t += o->items[i].qty * o->items[i].price; return t; }

"One of several variants" (sum types)

Rust   enum Payment { Upi { vpa: String }, Card { last4: String }, Cash }       + exhaustive match   ← best support
TS     type Payment = { kind: "upi"; vpa: string } | { kind: "card"; last4: string } | { kind: "cash" }
Python Upi | Card | Cash  (dataclasses) + match/case     (type checkers check exhaustiveness)
Go     an interface + concrete types + a type switch     (no exhaustiveness check)
C      enum tag + union of payloads                      (you keep the tag and union in sync)

Inheritance

Python, TS and C++ have class inheritance. Go and Rust deliberately don't: use composition (Go struct embedding, Rust fields) plus interfaces/traits. It's good advice in every language anyway (OOP).

Traps when switching

  • Go value vs pointer receivers: func (o Order) SetStatus(…) modifies a copy. Use func (o *Order) for anything that mutates.
  • Rust &self vs &mut self vs self: read, modify, or consume.
  • TS classes vs interfaces: interfaces vanish at runtime, so instanceof only works for classes. Use a discriminant field for unions.
  • Python mutable defaults in dataclasses: items: list = field(default_factory=list).

Practice

0.1 think Model a Shape with Circle and Rectangle and an area() operation in all five languages: variants in Rust (enum), TS (union), Python (match), Go (interface) and C (tagged union). Which makes a forgotten variant a compile error?

Rust's match does by default. TS does with a never check in the default branch. Python does only under a type checker with assert_never. Go and C won't tell you (C's -Wswitch warns for enum switches without a default).
