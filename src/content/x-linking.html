What happens between "compiled" and "running": object files, symbols, the linker, and the loader.

From many files to one program

main.c ─cc -c─► main.o ─┐ (object files: machine code + a SYMBOL TABLE util.c ─cc -c─► util.o ─┼─► LINKER (ld) ─► ./app listing what each defines and what it still needs) libm.a / libc.so ───────┘ resolves every "undefined" symbol to an address
gcc -c util.c                  # compile only → util.o
nm util.o                      # symbols: T = defined function, U = undefined (needed from elsewhere)
gcc main.o util.o -o app       # link
ldd ./app                      # shared libraries it needs at runtime (libc.so.6 …)
readelf -h ./app | head        # ELF header: the Linux executable format
objdump -d ./app | less        # disassemble

The loader

When you run a dynamic program, the kernel maps it into memory and starts the dynamic loader (ld-linux.so). The loader finds each needed .so (via the paths in the binary, LD_LIBRARY_PATH and /etc/ld.so.cache), maps it in, resolves symbols, and jumps to main. LD_PRELOAD can inject a library first, which is used for profilers and for hooking functions.

ABI and FFI

The ABI (application binary interface) fixes how functions receive arguments (registers or stack), how structs are laid out, and how names appear. Because every language can speak the C ABI, Python (ctypes, cffi), Go (cgo), Rust (extern "C") and Node (N-API) can all call C libraries. This is FFI (foreign function interface), and it's how NumPy, SQLite bindings and GPU libraries work.

#[no_mangle]
pub extern "C" fn add(a: i32, b: i32) -> i32 { a + b }   // build as a cdylib → callable from C, Python, Go

Practice

0.1 basic Build a tiny C library as both libutil.a and libutil.so, link a program against each, and compare the binary sizes and the ldd output.

Build the static version with ar rcs libutil.a util.o and the shared one with gcc -shared -fPIC -o libutil.so util.c. The static binary contains the code; the dynamic one lists libutil.so in ldd and needs LD_LIBRARY_PATH=. to run.
