Mapping URLs to screens in single-page apps.

In an SPA, the browser loads one HTML page. The router intercepts link clicks, updates the URL with the History API (history.pushState) without a reload, and renders the matching component. That's why deploying SPAs needs a fallback rule (the /* /index.html 200 you added for Netlify): refreshing /orders/42 must still serve index.html.

// React Router (data router)
const router = createBrowserRouter([
  { path: "/", element: <Layout />, children: [
    { index: true, element: <Home /> },
    { path: "orders", element: <Orders /> },
    { path: "orders/:id", element: <OrderDetail />, loader: ({ params }) => getOrder(params.id!) },
    { path: "*", element: <NotFound /> },
  ]},
]);
// inside components: const { id } = useParams(); const [sp, setSp] = useSearchParams(); navigate("/orders")

Nested routes share layouts (a sidebar stays mounted while the child view changes). Put filters and page numbers in the query string (?status=paid&page=2) so views are shareable and the back button behaves. Code-split per route with lazy() so users download only the screens they visit.
