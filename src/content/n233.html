Estimating and controlling what AI features cost.

cost/request = input_tokens × input_price + output_tokens × output_price      (prices per million tokens)
monthly      = requests/day × 30 × cost/request

Example (illustrative prices): complaint classifier, 2,000 input + 150 output tokens, 5,000 requests/day
  small model  @ $1 in / $5 out   → 2000×1e-6 + 150×5e-6 = $0.00275/req → ~$410/month
  large model  @ $5 in / $25 out  →                        $0.01375/req → ~$2,060/month
  + prompt caching of a 1,800-token static prefix (≈90% off cached reads) → the input cost drops sharply

Levers, roughly in order of impact

  1. The right model per task: route easy tasks to small models and escalate only hard ones.
  2. Prompt caching: put static instructions and documents first.
  3. Fewer tokens: trim the conversation history, retrieve fewer and better chunks, use compact formats, set max_tokens, ask for concise answers.
  4. The Batch API for offline jobs (typically about 50% off).
  5. Cache whole responses for repeated identical questions.
  6. Limit agent loops: step caps and budget checks (chapter 234).
  7. Self-hosting only at high, steady volume (chapter 231).

Measure cost per successful outcome (a resolved ticket, a correct extraction), not cost per call: a cheap model that fails half the time isn't cheap.

Practice

233.1 basic Estimate the monthly cost of a feature that summarises 200 store reports a day (about 3K tokens in, 300 out each) with a small and a large model.

Work it through with current prices: 200 × 30 × (3000 × in + 300 × out) / 1e6 per model. Then apply prompt caching for the shared instructions, or the Batch API since it isn't urgent.
