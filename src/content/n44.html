A branch is just a movable label. Once that sinks in, branching stops being scary.

What a branch actually is

A branch is a file containing one commit ID (cat .git/refs/heads/main). Committing on a branch moves its label forward to the new commit. HEAD points at the current branch. Creating a branch costs 41 bytes.

A ── B ── C ◄── main \ D ── E ◄── feature/stock ◄── HEAD
git switch -c feature/stock      # create + switch (the modern form of: git checkout -b)
git branch                       # list local branches (* = current)
git branch -vv                   # with upstream tracking info
git switch main                  # go back
git branch -d feature/stock      # delete (refuses if unmerged; -D forces)

Merging: two kinds

FAST-FORWARD (main has no new commits): THREE-WAY (both moved on): A ── B ── C ── D ── E A ── B ── C ── F ────── M ◄── main ▲ main just slides \ / D ── E ───┘ M has two parents
git switch main
git merge feature/stock          # fast-forward if possible, otherwise creates a merge commit M
git merge --no-ff feature/stock  # always make a merge commit (keeps the feature grouped in history)

Detached HEAD

git switch --detach <sha> (or checking out a tag) points HEAD straight at a commit, with no branch. You can look around and even commit, but those commits belong to no branch, and leaving strands them (reflog can still recover them). If you want to keep work done there: git switch -c new-branch.

Branching strategies

StrategyHowGood for
GitHub Flowmain is always deployable; short-lived feature branches; PR → review → merge → deploymost teams and web apps. Your default.
Trunk-basedeveryone merges to main at least daily; unfinished work hidden behind feature flagshigh-velocity teams with strong CI
Git Flowdevelop, release/*, hotfix/* branchesversioned software with scheduled releases; heavy for web apps
Release branchesmain + release/1.x for maintaining old versionslibraries and self-hosted products

Long-lived branches are the enemy: the longer a branch lives, the more it diverges and the worse the merge. Keep branches to days, not weeks.
