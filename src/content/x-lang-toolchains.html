What "compiled" changes day to day

  • Errors arrive earlier: Go, Rust and C (and TS's type checker) reject many mistakes before the program runs. In Python, most mistakes only appear when the line executes, so tests matter even more.
  • Deployment: a Go or Rust binary is one file you copy to a server. Python and Node need their runtime and dependencies installed (or a container).
  • Edit–run loop: interpreted languages start instantly; Rust compiles slowly (incremental builds help); Go compiles very fast.
  • Startup and speed: native binaries start in milliseconds and run CPU-heavy code 10–100× faster than CPython.

A minimal project in each

uv init wc-py && cd wc-py && uv run main.py
mkdir wc-ts && cd wc-ts && npm init -y && npm i -D typescript tsx @types/node && npx tsc --init && npx tsx main.ts
mkdir wc-go && cd wc-go && go mod init wc && go run .
cargo new wc-rs && cd wc-rs && cargo run
mkdir wc-c && cd wc-c && printf 'wc: main.c\n\tgcc -std=c17 -Wall -Wextra -g -o wc main.c\n' > Makefile && make

Practice

0.1 basic Create the five minimal projects above, each printing "hello from <language>". Time hyperfine on each hello-world binary or script.

Native binaries (C, Rust, Go) start in about 1 ms; Node in about 40 ms; Python in about 20 ms. Startup matters for CLIs run thousands of times, and barely matters for long-running servers.
