How an application actually starts from the operating system up, how each language turns source into a running program, and the everyday commands and toolchains you'll use.

1. Anatomy of an Application Startup: What Happens When Code Runs

When you type a command like python3 link.py, npm run dev, or go run . in your terminal, your computer doesn't magically "read" code. A precise cascade of operating system and runtime events takes place.

Step-by-Step: The Python Application Startup Lifecycle

Let's trace what happens when you run a Python script like python3 link.py in this repository:

  1. Process Creation: The shell executes execve("/usr/bin/python3", ["python3", "link.py"], envp). The OS kernel creates a new process, allocates private virtual memory pages, and maps the CPython executable into memory.
  2. CPython Initialization: CPython's Py_Initialize() sets up the runtime. It loads the built-in modules (sys, builtins like len(), print()), sets up sys.path for importing other files, and allocates the main thread state.
  3. Tokenizing & AST Generation: Python reads the characters of link.py from disk. The tokenizer converts the text into a stream of tokens, and the parser builds an Abstract Syntax Tree (AST) representing the program's structural grammar.
  4. Bytecode Compilation: Python compiles the AST into a Python code object containing bytecode instructions (e.g. LOAD_CONST, STORE_NAME, CALL_FUNCTION). If imported as a module, it caches this on disk in __pycache__/*.pyc.
  5. The Evaluation Loop (ceval.c): CPython's virtual machine enters its central loop. It maintains a Call Stack of frame objects. In link.py, it executes lines sequentially:
    • import os, re: locates the modules, loads their code objects, and binds them to the current namespace.
    • p = 'src/curriculum.ts'; s = open(p).read(): makes an OS syscall (openat, read) to load the file contents into a Python str object on the heap.
    • for line in ...:: creates an iterator and evaluates loop body bytecode instructions until exhausted.
  6. Process Exit: When execution reaches the end of the file or calls sys.exit(0), Python runs finalizers, collects garbage, closes open file descriptors, and returns exit code 0 to the operating system.

Step-by-Step: The JavaScript & TypeScript Startup Lifecycle

In web and full-stack development (like this Vite + React + TypeScript site):

  1. Vite Development Server (Node.js): When you run npm run dev, Node.js boots Google's V8 engine and the libuv event loop. Vite opens a TCP socket on http://localhost:5173 and listens for incoming browser HTTP requests.
  2. On-Demand Transpilation: Unlike traditional bundlers that compile every file before starting, Vite serves source code over native ES modules. When your browser requests src/main.tsx, Vite uses esbuild (written in Go) to strip TypeScript types and convert JSX into standard JavaScript in under 2 milliseconds.
  3. Browser Execution: The browser's V8 engine receives the JavaScript. It creates the Global Execution Context, executes top-level JavaScript, boots the React 19 root (createRoot(document.getElementById('root')!)), renders DOM nodes, and waits for user events via the browser Event Loop.

Step-by-Step: The Go Application Startup Lifecycle

Unlike Python and JavaScript, Go produces a statically linked native machine binary with no interpreter:

  1. Direct Execution: The OS kernel reads the ELF/Mach-O headers, maps memory, and jumps directly to the entry symbol (_rt0_amd64_linux or similar). No external runtime needs to be installed on the machine.
  2. Runtime Bootstrap (runtime.rt0_go): Before your main() function ever runs, Go's embedded runtime initializes:
    • Detects the number of CPU cores and initializes the M:N scheduler (mapping $M$ OS threads to $N$ goroutines via logical processors $P$).
    • Initializes memory allocators (mcache, mcentral, mheap) and the concurrent Garbage Collector.
    • Runs all package init() functions in topological dependency order.
  3. Launching main.main: The runtime creates the primary Goroutine and schedules it on an OS thread to run your func main().

3. What "Compiled vs Interpreted" Changes Day to Day

  • Errors arrive earlier: Go, Rust, C (and TypeScript's type checker) reject type mismatches, missing parameters, and typos before the program ever runs. In Python and standard JavaScript, errors only emerge when that exact line of code executes at runtime.
  • Deployment simplicity: A Go or Rust binary is a single self-contained file you copy to a bare Linux server. Python and Node require the interpreter, runtime environment, and node_modules or virtual environment installed on target machines.
  • Edit–run latency: Python and Node start interpreting instantly; Go compiles so fast it feels like a script (go run .); Rust compiles more slowly due to deep LLVM optimizations.
  • Startup overhead: Native binaries (Go, C) initialize in 1–2 milliseconds. Python takes ~20–30 ms. Node.js takes ~40–60 ms. For serverless functions (cold starts) and CLI tools, this is significant.

4. Minimal Project Scaffolding in Each Language

# Python with uv
uv init wc-py && cd wc-py && uv run main.py

# TypeScript with Node
mkdir wc-ts && cd wc-ts && npm init -y && npm i -D typescript tsx @types/node && npx tsc --init && npx tsx main.ts

# Go
mkdir wc-go && cd wc-go && go mod init wc && go run .

# Rust
cargo new wc-rs && cd wc-rs && cargo run

# C
mkdir wc-c && cd wc-c && printf 'wc: main.c\n\tgcc -std=c17 -Wall -Wextra -g -o wc main.c\n' > Makefile && make

Practice

100.1 basic Create the minimal projects above, each printing "hello from <language>". Time hyperfine on each hello-world binary or script.

Native binaries (C, Rust, Go) start in about 1 ms; Node in about 40 ms; Python in about 20 ms. Startup matters for CLIs run thousands of times, and barely matters for long-running servers.

100.2 intermediate Inspect the bytecode of a Python function using the standard library dis module: import dis; dis.dis(lambda x: x + 1).

You will see opcodes like LOAD_FAST 0 (x), LOAD_CONST 1 (1), and BINARY_OP 0 (+). This is the exact bytecode the CPython virtual machine loop executes.
