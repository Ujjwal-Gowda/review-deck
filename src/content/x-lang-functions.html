The same function five times

def split_price(paise: int, parts: int = 2) -> tuple[int, int]:
    return divmod(paise, parts)            # (each, remainder)
each, rem = split_price(1001, 3)
function splitPrice(paise: number, parts = 2): [number, number] {
  return [Math.floor(paise / parts), paise % parts];
}
const [each, rem] = splitPrice(1001, 3);
func splitPrice(paise, parts int) (each, rem int) {   // named results
    return paise / parts, paise % parts
}
each, rem := splitPrice(1001, 3)                      // no default parameters in Go
fn split_price(paise: u64, parts: u64) -> (u64, u64) {
    (paise / parts, paise % parts)                    // last expression = return value (no semicolon)
}
let (each, rem) = split_price(1001, 3);
void split_price(long paise, long parts, long *each, long *rem) {   // "multiple returns" via out-pointers
    *each = paise / parts; *rem = paise % parts;
}
long each, rem; split_price(1001, 3, &each, &rem);

How arguments are passed

Python and JS pass object references (mutating an argument is visible to the caller; rebinding it isn't). Go and C pass copies, so pass a pointer to let the callee modify. Rust moves ownership unless you pass a reference (&T, &mut T). Details in Memory & Value Semantics Across Languages.

Practice

0.1 basic Write make_counter(), which returns a function that increments and returns a private count, in Python, TS, Go and Rust. Why is it hard in C?

Python: nonlocal. TS: an arrow function capturing let n. Go: a func literal capturing n. Rust: let mut n = 0; move || { n += 1; n }, whose type is impl FnMut() -> i32. C has no closures: you'd pass a struct holding the state along with a function pointer.
