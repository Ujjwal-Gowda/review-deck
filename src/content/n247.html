The Golden Rule: Stop the Bleeding First

When an alert fires at 2:00 AM and production error rates spike from 0.01% to 15%, junior engineers freeze or attempt to read the entire codebase line-by-line looking for typos. Senior engineers follow a strict triage protocol: Mitigation precedes Diagnosis.

The 3 Pillars of Observability Correlation

Never search unstructured log files blindly. Always follow the narrowing funnel:

1. Metrics (The "What & Where")

High-cardinality time series data in Prometheus / Grafana. Shows aggregate error spikes, P99 latency jumps, and CPU saturation across services in seconds.

2. Traces (The "Why")

Distributed OpenTelemetry waterfall graphs. Shows the exact breakdown of time across HTTP Gateway → Database Query → Redis Cache → Third-Party API.

3. Structured Logs (The "Proof")

JSON log entries stamped with the request's trace_id. Lets you grep the exact error message and parameter payload for a single failing transaction.

The Essential Linux Production Toolkit

When you have shell access to a struggling node, these commands reveal what the Linux kernel is doing without restarting the process:

# 1. Check if the Linux Out-Of-Memory (OOM) Killer assassinated your process
dmesg -T | grep -E -i "killed process|oom-killer"

# 2. Inspect active network sockets, connection queues, and TCP states
# Look for SYN_RECV surges (SYN flood) or CLOSE_WAIT leaks (socket not closed by app)
ss -tulpn
ss -s

# 3. Profile system calls in real-time without recompilation
# Shows whether process is blocked on disk I/O, network reads, or mutex futex locks
strace -c -p 

# 4. Check open file descriptors (Catch "Too many open files" limits)
lsof -p  | wc -l
cat /proc//limits | grep "Max open files"

# 5. Non-invasive CPU & Memory Sampling for running apps
# Python:
py-spy top --pid 
# Go:
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=10

The 5 Most Common Production Culprits

SymptomRoot CauseDiagnostic TellPermanent Fix
API latency jumps from 20ms to 10,000ms simultaneously across all endpoints Database Connection Pool Exhaustion API logs show pool timeout: connection acquired in 10000ms while DB CPU is only 5%. Ensure every DB transaction is wrapped in try...finally { client.release(); }. Never make external HTTP calls inside a DB transaction!
Sudden CPU spike to 100% every hour at exact minute :00 Cache Stampede (Thundering Herd) Redis key expired; 5,000 concurrent web requests all miss cache and hit PostgreSQL with the same expensive query. Add Jitter to TTLs (TTL = 3600 + rand(0, 300)) or use SingleFlight / Mutex Locking on cache reload.
Node.js / Python memory climbs linearly over days until crash Global State / Event Listener Leak Memory profile shows millions of uncollected objects attached to global arrays or un-deregistered socket listeners. Avoid global mutable arrays; use WeakMap / WeakRef; inspect heap snapshots in Chrome DevTools.
HTTP 502 Bad Gateway from Nginx App Crash or Keep-Alive Timeout Mismatch Node.js keepAliveTimeout is shorter than Nginx's upstream keepalive timeout. Set Node.js server.keepAliveTimeout = 65000 (longer than Nginx's 60s default).
Drill: Why making an HTTP API call inside a DB transaction causes total site outage (Click to expand)

Scenario: An engineer writes: 

await db.query("BEGIN");
await db.query("UPDATE user_credits SET balance = balance - 10 WHERE id = $1", [userId]);
// External payment gateway call
await stripe.charges.create({ amount: 1000 }); 
await db.query("COMMIT");

Question: What happens if Stripe experiences a 15-second latency delay?

Answer: Total connection pool starvation!

While the API waits 15 seconds for Stripe's network response, the PostgreSQL database connection remains held open and the user row remains locked. Within 2 seconds of high traffic, all available database connections in the pool (e.g. 50 connections) are locked waiting on Stripe. Every other user trying to browse the homepage or read a product is blocked, bringing down the entire application.

Rule: NEVER perform external network I/O inside an open database transaction!
