The workload controllers that create and manage pods for you.

apiVersion: apps/v1
kind: Deployment
metadata: { name: api }
spec:
  replicas: 3
  selector: { matchLabels: { app: api } }
  strategy: { rollingUpdate: { maxUnavailable: 0, maxSurge: 1 } }   # zero-downtime rolling update
  template:
    metadata: { labels: { app: api } }
    spec:
      containers: [{ name: api, image: "ghcr.io/ujjwal/shop-api:1.4.2" }]   # + probes/resources as in chapter 136
kubectl set image deploy/api api=ghcr.io/ujjwal/shop-api:1.4.3   # (in real life: change the YAML in git)
kubectl rollout status deploy/api
kubectl rollout undo deploy/api                                  # roll back to the previous ReplicaSet
kubectl scale deploy/api --replicas=5
ControllerUse for
Deployment → ReplicaSet → Podsstateless services (almost everything)
StatefulSetstable identities and per-pod storage (db-0, db-1): databases, Kafka. Prefer managed databases where you can.
DaemonSetone pod per node: log collectors, monitoring agents, CNI
Jobrun to completion (a migration, a batch import), with retries
CronJobJobs on a schedule (schedule: "0 23 * * *")
