Postgres features worth knowing

  • Types: bigint identity keys (id bigint GENERATED ALWAYS AS IDENTITY), numeric for money, timestamptz (always, not timestamp), jsonb (indexable JSON), uuid, arrays, enums, ranges.
  • Constraints are your last line of defence: NOT NULL, CHECK (qty >= 0), UNIQUE, foreign keys, exclusion constraints.
  • Extensions: pgvector (embeddings), pg_trgm (fuzzy search), postgis (maps), pg_stat_statements (the slowest queries).
  • Roles: the app connects as a limited role, not the superuser. GRANT SELECT, INSERT, UPDATE ON orders TO app;
  • LISTEN/NOTIFY for simple pub/sub; SKIP LOCKED for job queues.

Operations

  • Connection pooling: each connection is a process (~10 MB). Use a pool in the app, plus PgBouncer when there are many app instances.
  • VACUUM/autovacuum cleans up dead row versions left by MVCC (chapter 98). Leave autovacuum on, and watch for table bloat.
  • Backups: pg_dump for logical dumps; base backups plus WAL archiving (pgBackRest, or a managed service) for point-in-time recovery. Test your restores.
  • Replication: streaming replicas for reads and failover.
  • Managed options: Supabase, Neon, RDS, Cloud SQL, Crunchy Bridge.
Security lens · PostgreSQL

Use separate roles for migrations (DDL) and the app (DML only); consider Row-Level Security for multi-tenant isolation; set statement_timeout to limit the damage from runaway queries.
