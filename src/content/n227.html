Evaluations: the tests of AI systems. Without them every prompt change is a guess.

  1. Collect cases: real inputs (logs, support tickets) covering typical, edge and adversarial cases, each with its expected output or grading criteria.
  2. Choose graders:
    • Code checks (cheapest, most reliable): valid JSON, the correct category, contains the order ID, under 100 words, the right tool called with the right arguments.
    • LLM-as-judge for fuzzy qualities (helpful, faithful to the sources, polite). Give it a clear rubric, ask for reasoning then a score, prefer pairwise comparisons, and check it against human labels.
    • Human review of a sample, especially early on and for high-stakes outputs.
  3. Run on every change (prompt, model, retrieval, tools), and compare scores against the baseline: a regression suite for behaviour.
  4. Track over time and add each production failure as a new case.
cases = json.load(open("evals/complaints.json"))
passed = 0
for c in cases:
    out = classify_complaint(c["input"])
    ok = out.category == c["expected_category"] and (c.get("order_id") is None or out.order_id == c["order_id"])
    passed += ok
    if not ok: print("FAIL", c["id"], out)
print(f"{passed}/{len(cases)} = {passed/len(cases):.0%}")

Tools: promptfoo, Braintrust, LangSmith, DeepEval, Inspect, or a script like the one above in CI. Evals are what let you switch models or cut costs confidently.
