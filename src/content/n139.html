HTTP routing from the internet to the right Service, with TLS.

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: shop
  annotations: { cert-manager.io/cluster-issuer: letsencrypt }   # automatic TLS certificates
spec:
  ingressClassName: nginx
  tls: [{ hosts: [api.freshon.in, app.freshon.in], secretName: shop-tls }]
  rules:
    - host: api.freshon.in
      http: { paths: [{ path: /, pathType: Prefix, backend: { service: { name: api, port: { number: 80 } } } }] }
    - host: app.freshon.in
      http: { paths: [{ path: /, pathType: Prefix, backend: { service: { name: web, port: { number: 80 } } } }] }

An Ingress resource is only a set of rules. An ingress controller (ingress-nginx, Traefik, a cloud load balancer controller) actually implements them, behind one LoadBalancer Service. cert-manager obtains and renews Let's Encrypt certificates. The newer Gateway API (Gateway + HTTPRoute) is the more expressive successor: header matching, traffic splitting for canaries, and cross-namespace routes.
