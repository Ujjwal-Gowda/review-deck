Doing several things at once in Python, and choosing the right tool given the GIL.

Work is…UseWhy
waiting on I/O (HTTP, DB, files), many tasksasynciothousands of concurrent waits on one thread
waiting on I/O with blocking librariesthreads (ThreadPoolExecutor)the GIL is released while waiting on I/O
CPU-heavy (parsing, image work, maths)processes (ProcessPoolExecutor)each process has its own interpreter and GIL, so it uses all cores

asyncio

import asyncio, httpx

async def fetch_price(client: httpx.AsyncClient, sku: str) -> int:
    r = await client.get(f"https://api.example.com/price/{sku}", timeout=5)   # await: yield to the loop while waiting
    r.raise_for_status()
    return r.json()["paise"]

async def main(skus):
    sem = asyncio.Semaphore(10)                      # at most 10 requests in flight
    async with httpx.AsyncClient() as client:
        async def one(s):
            async with sem: return await fetch_price(client, s)
        async with asyncio.TaskGroup() as tg:        # 3.11+: structured concurrency; cancels siblings on error
            tasks = [tg.create_task(one(s)) for s in skus]
    return {s: t.result() for s, t in zip(skus, tasks)}

prices = asyncio.run(main(["milk", "curd", "paneer"]))
# timeouts: async with asyncio.timeout(10): ...

Rules: never call blocking functions (time.sleep, requests.get, heavy CPU work) inside async code; use await asyncio.sleep, async libraries, or await asyncio.to_thread(blocking_fn).

Threads and processes via concurrent.futures

from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor, as_completed
with ThreadPoolExecutor(max_workers=8) as pool:              # blocking I/O
    futures = {pool.submit(download, url): url for url in urls}
    for fut in as_completed(futures):

Python 3.13+ has an experimental free-threaded build (no GIL), where threads can run CPU work in parallel. Libraries are still catching up.

In practice

Web APIs: FastAPI (async) or Django/Flask (threads). Scrapers and API fan-out: asyncio + httpx. Batch data crunching: processes, or better, vectorised libraries (NumPy, Polars) that release the GIL internally.

Practice

0.1 basic Check 50 URLs three ways: sequentially, with ThreadPoolExecutor(10), and with asyncio + httpx (Semaphore(10)). Time each.

Sequential time is roughly the sum of the latencies; both concurrent versions take roughly the slowest batch of 10, about 5–10× faster. asyncio and threads end up similar here; asyncio scales further (thousands of connections) with less memory.
