A binary tree with one rule (smaller keys to the left, larger to the right) that makes search, insert and sorted traversal fast.

insert 50, 30, 70, 20, 40, 60, 80: 50 / \ 30 70 rule at EVERY node: left subtree < node < right subtree / \ / \ 20 40 60 80 search 60: 60 > 50 → go right; 60 < 70 → go left; found. 3 comparisons for 7 keys (log₂ 7 ≈ 3)
class Node:
    def __init__(self, key): self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None: return Node(key)
    if key < root.key: root.left = insert(root.left, key)
    elif key > root.key: root.right = insert(root.right, key)
    return root                                  # duplicates ignored

def search(root, key):
    while root and root.key != key:
        root = root.left if key < root.key else root.right
    return root

def minimum(root):
    while root.left: root = root.left
    return root

Deleting: three cases

1. a leaf (20): just remove it 2. one child (70 with 60): replace the node with its child 3. two children (50): replace its key with its in-order SUCCESSOR (the smallest key in its right subtree, 60), then delete that successor from the right subtree (it has at most one child)
def delete(root, key):
    if root is None: return None
    if key < root.key: root.left = delete(root.left, key)
    elif key > root.key: root.right = delete(root.right, key)
    else:
        if root.left is None: return root.right          # cases 1 and 2
        if root.right is None: return root.left
        succ = minimum(root.right)                       # case 3
        root.key = succ.key
        root.right = delete(root.right, succ.key)
    return root

Sorted for free

An in-order traversal visits the keys in ascending order. That's why BSTs (and their balanced cousins) back ordered maps: range queries ("keys between 30 and 60"), floor/ceiling ("the largest price ≤ ₹500"), and min and max, none of which a hash table can do.

The catch: degeneration

insert 10, 20, 30, 40, 50 (already sorted): 10 \ 20 \ 30 ← it's a linked list now: search is O(n), not O(log n) \ 40

The fix is self-balancing trees, which rotate nodes to keep the height about log n (Balanced Trees). In real code, use the library: Rust BTreeMap, Java TreeMap, C++ std::map; in Python, the sortedcontainers package or bisect on a sorted list.

Practice

0.1 basic Write is_valid_bst(root). Why is comparing each node only with its direct children wrong?

A node deep in the left subtree must be less than every ancestor that it sits to the left of, not just its parent. Pass down bounds: valid(n, lo, hi) checks lo < n.key < hi, then recurses with (lo, n.key) on the left and (n.key, hi) on the right. Alternatively, an in-order traversal must be strictly increasing.
