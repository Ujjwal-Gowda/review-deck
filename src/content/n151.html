Getting and renewing certificates automatically, so they never expire in production.

ACME is the protocol Let's Encrypt uses. Your server proves it controls the domain, then gets a 90-day certificate. There are two main ways to prove control:

ChallengeHowUse when
HTTP-01serve a token at http://domain/.well-known/acme-challenge/…a public web server on port 80
DNS-01create a TXT record _acme-challenge.domain via your DNS provider's APIwildcard certificates (*.freshon.in), or internal servers not reachable from outside
sudo certbot --nginx -d api.freshon.in           # obtain a certificate and configure nginx; renewal is installed as a systemd timer
sudo certbot renew --dry-run                      # prove that renewal works
# Caddy, Traefik, Netlify and Kubernetes cert-manager do all of this automatically
  • Monitor expiry anyway: alert 14 days before. Automated renewals fail silently (a firewall change, a DNS API key rotated).
  • Serve the full chain. Redirect HTTP to HTTPS and add HSTS. Test at ssllabs.com.
  • Internal services: mkcert for development; a private certificate authority (step-ca, Vault PKI) for mTLS between services.

Practice

151.1 basic Set up a local HTTPS dev certificate with mkcert and serve a site on https://localhost.

mkcert -install && mkcert localhost, then configure the dev server with the key and cert (Vite: the server.https option). The browser trusts it because mkcert added a local CA.
