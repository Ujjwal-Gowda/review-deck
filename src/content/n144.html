Packaging and templating Kubernetes manifests for many environments.

helm repo add bitnami https://charts.bitnami.com/bitnami
helm install cache bitnami/redis --set auth.enabled=true -n shop --create-namespace   # install third-party software
helm upgrade --install api ./charts/api -f values-prod.yaml    # your own chart, with per-environment values
helm list -A; helm rollback api 3; helm template ./charts/api  # render to plain YAML to inspect it

A chart is templated YAML (templates/deployment.yaml using {{ .Values.image.tag }}) plus default values.yaml. Helm tracks releases, so upgrades and rollbacks are one command. It's great for installing off-the-shelf software (ingress-nginx, cert-manager, Prometheus).

k8s/
  base/            deployment.yaml service.yaml kustomization.yaml
  overlays/
    staging/       kustomization.yaml  (patch: replicas 1, image tag, ConfigMap)
    prod/          kustomization.yaml  (patch: replicas 3, resources, HPA)
kubectl apply -k k8s/overlays/prod     # Kustomize: patches over plain YAML, no templating language

Helm vs Kustomize: Helm has templating plus release management, and is best for distributing software. Kustomize is plain YAML with patches, simpler for your own apps. Many teams use both, with Argo CD applying them from git.
