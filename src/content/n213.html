A second, more precise pass that reorders the retrieved candidates.

Embedding search compares a query vector against document vectors that were computed separately (a bi-encoder: fast, but coarse). A cross-encoder reranker reads the query and each candidate together and scores how relevant they are. It's much more accurate, and too slow to run over everything, so run it only on the top ~50 candidates.

query → hybrid retrieval (top 50, fast, high recall) → reranker (score 50 pairs) → top 5 → LLM prompt
from sentence_transformers import CrossEncoder              # local: e.g. a BGE reranker model
reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")
scores = reranker.predict([(query, c.body) for c in candidates])
top = [c for _, c in sorted(zip(scores, candidates), key=lambda t: -t[0])][:5]
# hosted alternatives: Cohere Rerank, Voyage rerank, Jina reranker
  • Rerankers usually give the largest single quality gain in a RAG pipeline.
  • Tune k: retrieve enough candidates to catch the answer (recall), then pass few enough to the LLM to keep it focused and cheap (precision). Too many chunks dilute attention and cost tokens.
  • Drop candidates below a score threshold. Returning "I don't know" beats answering from weak context.
