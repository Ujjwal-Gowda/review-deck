You'll almost never implement these at work. Understand the guarantee (O(log n) regardless of insertion order) and the shape (why a database index is only 3–4 levels deep, which explains why indexed lookups are fast: Indexes). Implementing an AVL tree once is still excellent practice in careful pointer manipulation.

Practice

0.1 think A B+ tree node fits 200 keys. How many levels are needed for 1 billion rows? What does that mean for disk reads per lookup?

200¹ = 200, 200² = 40,000, 200³ = 8 million, 200⁴ = 1.6 billion. So 4 levels. The top levels stay cached in RAM, so a lookup usually costs 1–2 actual disk reads.
