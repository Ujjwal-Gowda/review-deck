Structuring C code: functions, declarations vs definitions, header files, and how multiple files become one program.

Functions

static long apply_tax(long paise) {        /* static: visible only in this file */
    return paise * 105 / 100;
}
void swap(int *a, int *b) {                 /* C passes BY VALUE; pointers let a function modify the caller's variables */
    int t = *a; *a = *b; *b = t;
}
int parse_qty(const char *s, int *out) {    /* return a status; put the result through an out-parameter */
    char *end; long v = strtol(s, &end, 10);
    if (*end != '\0' || v < 1 || v > 50) return -1;
    *out = (int)v; return 0;
}

Declaration vs definition

A declaration (a prototype) says "this function exists, with these types". A definition is the body. You can call a function after its declaration; the linker later connects the call to the definition, which may live in another file.

Headers: the public interface

/* stock.h */
#ifndef STOCK_H                  /* include guard: prevents double inclusion */
#define STOCK_H
#include <stddef.h>
typedef struct Stock Stock;      /* opaque: users can't see the fields */
Stock *stock_new(size_t capacity);
int stock_reserve(Stock *s, const char *sku, int qty);   /* 0 = ok, -1 = error */
void stock_free(Stock *s);
#endif

/* stock.c */
#include "stock.h"
#include <stdlib.h>
struct Stock { char (*skus)[16]; int *qty; size_t n, cap; };
Stock *stock_new(size_t cap) { /* … */ }

/* main.c */
#include "stock.h"
int main(void) { Stock *s = stock_new(64); /* … */ stock_free(s); }

The build

# Makefile (recipe lines must start with a TAB)
CC = gcc
CFLAGS = -std=c17 -Wall -Wextra -Wpedantic -g
OBJS = main.o stock.o

app: $(OBJS)
	$(CC) $(CFLAGS) -o $@ $(OBJS)

%.o: %.c stock.h
	$(CC) $(CFLAGS) -c $<

clean:
	rm -f app $(OBJS)

Each .c is compiled separately into a .o; the linker joins them. "undefined reference to stock_new" means the definition wasn't linked (a missing .o or -l flag). "implicit declaration" means you forgot the #include (Linking).
