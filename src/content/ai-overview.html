How to approach embedding AI into products: architectures, cost vs latency tradeoffs, and evaluating whether an LLM or ML model is even needed.

Core Mental Models: Rule-Based vs ML vs LLM

Before writing code, classify your task into one of three buckets:

  • Deterministic / Rule-based: Syntax parsing, validation, arithmetic, precise business logic. Never use an LLM here.
  • Specialized Classical ML / Distilled: Spam classification, fraud scoring, recommendation re-ranking. Lower latency (<10ms), predictable costs.
  • Generative / Reasoning LLMs: Open-ended summarization, extraction from unstructured messy text, flexible semantic understanding. High latency (200ms - 5s), per-token cost.
Client Request ──► Feature Flag / Router ──► [Static Rules / Cache] (0ms, $0.00) │ ├──► [Semantic Cache / Embeddings] (20ms, $0.0001) │ ├──► [Small Fine-Tuned / Fast Model] (150ms, $0.001) │ └──► [Frontier Reasoning LLM] (1500ms, $0.03)

Integration Architecture Patterns

  • Direct Synchronous Proxy: User request waits for LLM completion. Only acceptable for sub-second tasks or background workers.
  • Server-Sent Events (SSE) Streaming: Stream tokens directly to UI as they decode. Perceived latency drops from 4s to 250ms (Time-To-First-Token).
  • Asynchronous Job Queue: For deep analysis or document processing. Return 202 Accepted with a job ID, run via Celery/BullMQ, notify client via WebSockets or polling.
Warning · Cognitive Bias & Cost Spirals

Don't fall into the trap of using a frontier $15/1M token model where an open-weights 8B model or regex would work. Always measure cost per successful user outcome.
