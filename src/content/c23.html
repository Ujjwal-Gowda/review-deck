The layer every program stands on.

ConceptWhat to know
Kernel vs user spaceThe kernel has full hardware access; programs run restricted and ask the kernel for things.
System callThat request: open, read, write, fork, mmap. strace -f python3 x.py shows every one.
Virtual memoryEvery process sees its own private address space; the MMU maps it to physical RAM in pages (4 KB). This gives isolation between processes.
Swap / pagingWhen RAM is full, pages go to disk and everything slows to a crawl ("thrashing"). With 8 GB RAM and a browser plus Remotion, this is what makes your machine lag.
OOM killerLinux kills a process when memory runs out entirely.
SchedulerDecides which thread runs on which core and when (time slices, priorities, nice).
File descriptorAn integer handle to an open file, socket or pipe. Limits: ulimit -n.
SignalsAsync notifications: SIGINT (Ctrl-C), SIGTERM (polite stop), SIGKILL (forced; can't be caught).
fork/execHow Unix starts programs: clone the process, then replace it with a new program.
Permissions / usersOwner/group/other with rwx; root; least privilege.
FilesystemInodes, directories, hard vs symbolic links, mount points. fsync is what makes data really durable.
ContainersDocker = processes isolated with namespaces + cgroups, sharing the host kernel. Lighter than VMs, which emulate whole machines with their own kernels.

Practice

6.1 basic Run strace -c ls /tmp. Which system calls dominate, and why does a simple ls need so many?

Mostly openat, mmap, read, fstat and getdents64. Loading the dynamic libraries and locale files happens before any directory is even read, which is why process startup has a real cost.
