Persistent storage for pods that need to keep data.

StorageClass (how to provision: e.g. gp3 SSD, with a reclaim policy) ↑ dynamic provisioning PersistentVolumeClaim ("I need 20Gi, ReadWriteOnce") ──bound──► PersistentVolume (an actual cloud disk) ↑ referenced by Pod / StatefulSet volumeClaimTemplates (one PVC per replica: data-db-0, data-db-1)
Access modeMeaning
ReadWriteOncemounted read-write by one node (a cloud block disk). The usual mode.
ReadWriteManymany nodes at once (NFS/EFS-type storage)
ReadOnlyManyshared read-only

Watch the reclaim policy: Delete destroys the disk when the PVC is deleted, while Retain keeps it. Block disks are tied to one availability zone, so a pod can only move to nodes in that zone. Running databases in Kubernetes is possible (with operators like CloudNativePG), but managed databases are simpler for most teams.

Practice

142.1 think A StatefulSet database pod was rescheduled and is stuck Pending. What's a likely cause involving volumes?

Its PersistentVolume is a zonal disk in zone A, but there's no schedulable node left in zone A. The pod can only run where its disk can attach.
