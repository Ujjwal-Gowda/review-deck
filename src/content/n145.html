Controlling who can do what inside the cluster: humans, CI and the pods themselves.

apiVersion: rbac.authorization.k8s.io/v1
kind: Role                                  # namespaced (ClusterRole = cluster-wide)
metadata: { namespace: shop, name: deployer }
rules:
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["get", "list", "patch", "update"]
---
kind: RoleBinding
apiVersion: rbac.authorization.k8s.io/v1
metadata: { namespace: shop, name: ci-deployer }
subjects: [{ kind: ServiceAccount, name: ci, namespace: shop }]
roleRef: { kind: Role, name: deployer, apiGroup: rbac.authorization.k8s.io }
  • Namespaces separate teams and environments (shop-staging, shop-prod) and scope RBAC, quotas and network policies.
  • Every pod runs as a ServiceAccount. Give apps their own, with minimal rights (usually none), and set automountServiceAccountToken: false if the app doesn't call the API.
  • Check permissions with kubectl auth can-i delete pods -n shop --as system:serviceaccount:shop:ci.
  • Pod Security Standards (the restricted profile): non-root, no privilege escalation, dropped capabilities, enforced per namespace.
