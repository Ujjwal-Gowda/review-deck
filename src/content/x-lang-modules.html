Typical project layouts

Python

shop/
  pyproject.toml  uv.lock
  src/shop/__init__.py
  src/shop/orders.py
  src/shop/cli.py
  tests/test_orders.py

TypeScript

shop/
  package.json  tsconfig.json
  src/index.ts
  src/orders/orders.ts
  src/orders/orders.test.ts
  dist/   (build output, gitignored)

Go

shop/
  go.mod  go.sum
  cmd/shop/main.go        (package main)
  internal/orders/orders.go
  internal/orders/orders_test.go

Rust

shop/
  Cargo.toml  Cargo.lock
  src/main.rs   (binary)
  src/lib.rs    (library root: mod orders;)
  src/orders.rs
  tests/integration.rs

C

shop/
  Makefile
  include/orders.h
  src/orders.c  src/main.c
  tests/test_orders.c
  build/  (objects, gitignored)

Importing

Py  from shop.orders import place_order          TS  import { placeOrder } from "./orders/orders.js";
Go  import "example.com/shop/internal/orders"      →  orders.PlaceOrder(...)
Rs  use crate::orders::place_order;               C   #include "orders.h"  (+ link orders.o)

Traps

  • Python imports depend on how you run the program. Use python -m shop.cli or an installed entry point, not python src/shop/cli.py.
  • TS/ESM imports often need the .js extension even in .ts files (NodeNext resolution).
  • Go forbids import cycles and unused imports: both are compile errors.
  • Rust modules must be declared (mod orders;) in the parent before they exist.
  • C headers need include guards (#ifndef ORDERS_H), and "undefined reference" errors come from the linker, not the compiler (Linking).
