root, sudo and least privilege

root (UID 0) bypasses all permission checks. sudo runs one command as root and logs it. Run services as dedicated unprivileged users. A web server that's hacked while running as root is a hacked machine.

Special bits

setuid (s in the owner's x slot): the program runs as its file's owner. passwd uses this to edit /etc/shadow. sticky bit on /tmp (t): everyone can write there, but you can only delete your own files. ACLs (setfacl/getfacl) grant per-user permissions beyond owner/group/other.

chmod 777

It means any user or process on the machine can overwrite the file. A "permission denied" error means find who needs access and grant exactly that: the right owner, the right group, or a narrower mode.

55.1 basic SSH says "UNPROTECTED PRIVATE KEY FILE". Fix it with one command, and explain why ssh cares.

chmod 600 ~/.ssh/id_ed25519. If other users can read your private key, it's no longer private, so ssh refuses to use it.

Security lens · Permissions

Most Linux privilege escalations exploit over-broad permissions: world-writable scripts run by root, secrets readable by all users, and unnecessary setuid binaries. Audit with find / -perm -4000 and find /etc -perm -o+w.
