Thinking recursively: the patterns, the costs, and converting recursion to loops.

Chapter 10 introduced base cases and the call stack. This chapter is about designing recursive solutions.

The recipe

  1. Define the function's contract in words: "size(dir) returns the total bytes under dir."
  2. Base case(s): the smallest inputs you can answer directly (an empty list, a leaf node, n = 0).
  3. Recursive case: express the answer using the same function on smaller inputs, and trust it (the leap of faith).
  4. Check progress: every call must move strictly toward a base case.
from pathlib import Path
def size(p: Path) -> int:
    if p.is_file():                         # base case
        return p.stat().st_size
    return sum(size(child) for child in p.iterdir())   # a directory's size = the sum of its children's

def permutations(items):
    out = []
    def go(path, remaining):
        if not remaining:                       # base: a full arrangement
            out.append(path[:]); return
        for i, x in enumerate(remaining):
            path.append(x)                      # choose
            go(path, remaining[:i] + remaining[i+1:])
            path.pop()                          # un-choose (backtrack)
    go([], items)
    return out

Overlapping subproblems → memoisation

If the same call happens many times (naive fib calls fib(30) about 832,000 times), cache results by argument. That turns exponential into polynomial time, and it's the doorway to dynamic programming (chapter 19).

use std::collections::HashMap;
fn ways(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {   // stair-climbing: 1 or 2 steps at a time
    if n <= 1 { return 1; }
    if let Some(&v) = memo.get(&n) { return v; }
    let v = ways(n - 1, memo) + ways(n - 2, memo);
    memo.insert(n, v);
    v
}

A tail call is a recursive call that's the very last action (return f(n-1, acc*n)). Languages that guarantee tail-call optimisation (Scheme, and many functional languages) reuse the frame, so it behaves like a loop. In your five languages, don't rely on it: for deep or unbounded depth, use an explicit stack.

Recursion → iteration with an explicit stack

func sizeIter(root string) (int64, error) {
    var total int64
    stack := []string{root}                       // the explicit stack replaces the call stack
    for len(stack) > 0 {
        p := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        info, err := os.Lstat(p)
        if err != nil { return 0, err }
        if !info.IsDir() { total += info.Size(); continue }
        entries, err := os.ReadDir(p)
        if err != nil { return 0, err }
        for _, e := range entries { stack = append(stack, filepath.Join(p, e.Name())) }
    }
    return total, nil
}

Swap the stack for a queue and you get breadth-first order: the same trick as DFS vs BFS in chapter 18.

def depth(x):
    if not isinstance(x, list): return 0
    return 1 + max((depth(i) for i in x), default=0)
21.2 think Write all subsets of a list (the power set) recursively in Rust, returning Vec<Vec<i32>>. What's its complexity?
fn subsets(xs: &[i32]) -> Vec<Vec<i32>> {
    match xs.split_first() {
        None => vec![vec![]],
        Some((&h, rest)) => {
            let without = subsets(rest);
            let with: Vec<_> = without.iter().map(|s| { let mut v = vec![h]; v.extend(s); v }).collect();
            [without, with].concat()
        }
    }
}

O(n·2ⁿ): 2ⁿ subsets, each up to n long.
