Allocating memory at runtime, and the discipline that keeps C programs free of leaks and crashes.

The four functions

CallDoesReturns
malloc(bytes)allocates uninitialised memorya pointer, or NULL on failure
calloc(n, size)allocates n × size bytes, zeroeda pointer or NULL
realloc(p, bytes)resizes (may move the block)the new pointer or NULL, in which case the old block is still valid
free(p)releases itnothing; free(NULL) is safe
int *nums = malloc(n * sizeof *nums);            /* sizeof *ptr: stays correct if the type changes */
if (nums == NULL) { perror("malloc"); return -1; }

int *bigger = realloc(nums, 2 * n * sizeof *nums);
if (bigger == NULL) { free(nums); return -1; }   /* NEVER nums = realloc(nums, …): on failure you'd leak nums */
nums = bigger;

free(nums);
nums = NULL;                                      /* avoids accidental use-after-free / double free */

Ownership: decide and document who frees

/* Returns a newly allocated string. The CALLER must free() it. */
char *order_label(const Order *o);

/* Borrows s; doesn't keep it after returning. */
void log_label(const char *s);

/* Takes ownership of items; frees them in cart_free(). */
Cart *cart_new(Item *items, size_t n);

The goto-cleanup pattern

int process(const char *path) {
    int rc = -1;
    FILE *f = NULL; char *buf = NULL;
    f = fopen(path, "r");            if (!f) goto out;
    buf = malloc(4096);              if (!buf) goto out;
    if (!fgets(buf, 4096, f))        goto out;
    /* … work … */
    rc = 0;
out:                                  /* one exit path frees everything that was acquired */
    free(buf);
    if (f) fclose(f);
    return rc;
}

For many small objects with the same lifetime, an arena (one big block handed out piece by piece and freed all at once) is simpler and faster than individual frees. It's a common pattern in parsers and game engines.

Practice

0.1 basic Implement a growable IntVec (push, get, free) with capacity doubling, then deliberately introduce a leak, a use-after-free and an overflow, and see how ASan reports each. (It's also the vec_push drill.)

Build with -g -fsanitize=address. A leak shows as "detected memory leaks" with the allocation's stack trace; use-after-free and overflow show the bad access, the allocation and the free locations. Reading these reports is a core C skill.
