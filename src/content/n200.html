The transformer architecture, one block at a time.

tokens → embeddings (+ position information) ┌─────────────── × N layers ────────────────┐ │ x = x + MultiHeadSelfAttention(Norm(x)) │ tokens exchange information │ x = x + FeedForward(Norm(x)) │ each position is transformed independently (MLP, often SwiGLU) └────────────────────────────────────────────┘ → final norm → linear layer to the vocabulary → softmax → next-token probabilities

Self-attention

Each token produces a Query, a Key and a Value vector (learned projections). The attention weights are softmax(Q·Kᵀ / √d): how much each token should look at each other token. The output is the weighted sum of the Values. A causal mask stops tokens from looking ahead (which is what makes it a generator). Multi-head attention runs this in parallel with different projections, so different heads learn different relationships (syntax, coreference, position).

  • Positional information: attention itself is order-blind, so position is injected. Modern LLMs use RoPE (rotary embeddings), which also helps extend context length.
  • Cost: attention is O(n²) in sequence length. Hence FlashAttention (memory-efficient kernels), GQA (a smaller KV cache: chapter 208), and sliding-window or linear-attention variants.
  • Variants: encoder-only (BERT: understanding and embeddings), decoder-only (GPT, Claude, Llama: generation), encoder-decoder (T5, Whisper: translation, speech).
  • Mixture of Experts: the feed-forward sublayer is replaced by many "experts", and a router picks 1–2 per token.

To really understand it: Karpathy's "Let's build GPT: from scratch, in code" (nanoGPT), and "The Illustrated Transformer" by Jay Alammar.

Early samples are gibberish, and after training they're Shakespeare-shaped text. Seeing a transformer learn is the best way to demystify it.
