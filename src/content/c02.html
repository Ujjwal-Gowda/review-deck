What data is, how it's represented, and what a variable really is.

Values and types

A value is a piece of data: 42, 3.14, "hi", True. Every value has a type, which decides (a) how it's stored in bits and (b) which operations make sense. You can add two numbers; you can't meaningfully divide a string by a boolean.

How integers are stored: binary

Computers store everything in bits (0 or 1). 8 bits = 1 byte. A number in binary works like decimal but with powers of 2:

bit value: 128 64 32 16 8 4 2 1 13 = 0 0 0 0 1 1 0 1 (8 + 4 + 1) 255 = 1 1 1 1 1 1 1 1 (max for one unsigned byte)

A fixed-size integer type has a fixed range. An unsigned 8-bit (u8) holds 0 to 255. A signed 32-bit (i32) holds −2,147,483,648 to 2,147,483,647 (negative numbers use two's complement: flip all the bits and add 1).

Overflow: what happens at 255 + 1 in 8 bits? Languages disagree, and it matters:

unsigned char u = 255; u = u + 1;   // wraps to 0 (defined for unsigned)
int i = 2147483647;    i = i + 1;   // UNDEFINED BEHAVIOUR in C: anything may happen
let x: u8 = 255;
let y = x + 1;          // debug build: panics "attempt to add with overflow"
let z = x.wrapping_add(1);   // explicit: 0
let w = x.checked_add(1);    // explicit: None
print(2 ** 200)   # Python ints grow as needed: no overflow, ever (but slower)

Hexadecimal (base 16, digits 0–9 a–f) is shorthand for binary: each hex digit is exactly 4 bits. 0xFF = 255 = 0b11111111. You'll see hex for memory addresses and colours (#2FA24F).

How decimals are stored: floating point

Floats use the IEEE 754 standard: a sign, an exponent and a fraction, like scientific notation in binary. The crucial consequence: most decimal fractions can't be represented exactly, just as 1/3 can't be written exactly in decimal.

>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
>>> abs((0.1 + 0.2) - 0.3) < 1e-9     # compare with a tolerance instead
True
>>> import math; math.isclose(0.1 + 0.2, 0.3)
True
Rule

Never use floats for money. Use integers in the smallest unit (paise/cents: ₹12.50 → 1250) or a decimal type (decimal.Decimal in Python, BigDecimal in Java). Never compare floats with ==; use a tolerance.

Floats also have special values: inf, -inf and nan ("not a number", from 0/0 in many languages). nan != nan is true, which famously breaks sorting and equality checks.

Variables: names, not boxes (in most modern languages)

A variable is a name bound to a value. There are two mental models, and knowing which one your language uses is essential:

"BOX" model (C, Go, Rust for plain values) "LABEL" model (Python, JS, Java for objects) int a = 5; int b = a; a = [1, 2]; b = a ┌─a─┐ ┌─b─┐ a ──┐ │ 5 │ │ 5 │ two separate boxes; ├──► [1, 2] one object, └───┘ └───┘ changing b leaves a alone b ──┘ two labels
a = [1, 2]
b = a            # b is another NAME for the same list
b.append(3)
print(a)         # [1, 2, 3]: surprise, unless you have the label model in your head

x = 5
y = x
y = y + 1        # rebinding y to a NEW int object; ints are immutable
print(x)         # 5

This one idea (aliasing) causes a huge share of real-world bugs. Chapter 10 goes deep on it.

Static vs dynamic typing; strong vs weak typing

Two independent axes, often confused:

  • Static typing: types are checked before running (at compile time). The variable has a type. C, Go, Rust, Java, TypeScript. Dynamic typing: types are checked while running. The value has a type; the variable doesn't. Python, JS, Ruby.
  • Strong typing: the language refuses to silently mix incompatible types. Weak typing: it silently converts ("coerces").
"5" + 3        # TypeError: Python is dynamic but STRONG
"5" + 3        // "53"   JS is dynamic and WEAK: it coerces
"5" - 3        // 2      …inconsistently
[] + {}        // "[object Object]"
0 == ""        // true   use === (strict equality) always
var n int = 5
var s string = "5"
// n + s   → compile error before the program ever runs: static and strong

Type inference gives static typing without writing every type: x := 5 (Go), let x = 5; (Rust). The compiler figures out x is an integer. Python has optional type hints (def f(x: int) -> str:) checked by external tools like mypy, not at runtime.

Constants and immutability

let x = 5;       // immutable by default in Rust
// x = 6;        // compile error
let mut y = 5;   // opt in to mutation
y += 1;

Rust, and functional languages, make immutability the default because values that can't change can't be changed by surprise. In JS, const makes the binding constant but not the object: const a = []; a.push(1) is allowed. Python has no real constants; UPPER_CASE names are a convention.

Type conversion

int("42")       # 42
int("4.2")      # ValueError
int(4.9)        # 4    truncates toward zero, doesn't round
round(4.5)      # 4    "banker's rounding": ties go to the even number!
float("3.5")    # 3.5
str(42)         # "42"
bool(0), bool(""), bool([]), bool(None)   # all False ("falsy")
bool("False")   # True, because it's a non-empty string

Exercises

2.1 basic By hand: convert 37 to binary and 0x2A to decimal. Then check with bin(37) and 0x2A in Python.

37 = 32 + 4 + 1 = 100101. 0x2A = 2×16 + 10 = 42.

2.2 basic Predict the output, then run it: a = [0]; b = a; b = b + [1]; print(a). Now replace b = b + [1] with b += [1]. Explain the difference.

First prints [0]: b + [1] builds a new list and rebinds b to it. Second prints [0, 1]: for lists, += mutates in place (it calls __iadd__, which is like extend), and a is the same object. Same-looking syntax, different semantics.

2.3 think Write a function that adds up prices [19.99, 5.01, 0.10] correctly to 25.10. Do it without floats.
def total(prices: list[str]) -> str:
    paise = 0
    for p in prices:
        rupees, _, frac = p.partition(".")
        paise += int(rupees) * 100 + int((frac + "00")[:2])
    return f"{paise // 100}.{paise % 100:02d}"

print(total(["19.99", "5.01", "0.10"]))   # 25.10
# or: from decimal import Decimal; sum(map(Decimal, ["19.99","5.01","0.10"]))

Note that the input is strings: once a value is a float, precision is already lost.

2.4 think In C, what does printf("%d\n", (unsigned char)300); print, and why?

44. 300 in binary is 1 0010 1100 (9 bits). Keeping only the low 8 bits gives 0010 1100 = 44. It's the same as 300 mod 256.
