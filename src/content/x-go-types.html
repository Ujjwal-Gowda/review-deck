Go's Type Philosophy: Composition Over Inheritance

Go has no classes, no inheritance hierarchies, and no implements keyword. Objects are modeled as concrete structs, behavior is attached via methods, and interfaces are satisfied implicitly (duck typing verified at compile time). This keeps dependencies decoupled and testing straightforward.

Part 1: Structs, Receivers & Constructors

Methods are functions with an explicit receiver declared before the function name:

package domain

import "sync"

type Order struct {
	ID         string `json:"id"`
	TotalCents int64  `json:"totalCents"`
	items      []string // unexported (private to package)
	mu         sync.Mutex
}

// Constructor convention: New returns pointer
func NewOrder(id string) *Order {
	return &Order{
		ID:    id,
		items: make([]string, 0, 8), // Pre-allocate initial slice
	}
}

// Pointer Receiver (*Order):
// MUST use pointer receiver if:
// 1. Method mutates struct fields
// 2. Struct contains locks (sync.Mutex CANNOT be copied!)
// 3. Struct is large (prevents copying bytes on every call)
func (o *Order) AddItem(sku string, priceCents int64) {
	o.mu.Lock()
	defer o.mu.Unlock()
	o.items = append(o.items, sku)
	o.TotalCents += priceCents
}

// Value Receiver (Order):
// Receives an independent stack copy. Mutation is invisible to caller.
func (o Order) ItemCount() int {
	return len(o.items)
}

Part 2: Interfaces Under the Hood (iface & eface)

An interface variable is not a direct pointer. At runtime, an interface is a 16-byte dual-pointer header:

The Infamous "Typed Nil" Disaster in Go

An interface in Go is only equal to nil if BOTH tab == nil AND data == nil.

If you assign a concrete nil pointer to an interface, the interface's tab pointer is NOT nil! This causes the classic bug where an error check passes even when the error is nil:

type CustomErr struct{}
func (e *CustomErr) Error() string { return "boom" }

func fail() error {
    var err *CustomErr = nil // Concrete pointer is nil
    return err               // ❌ RETURNS an iface with tab=*CustomErr and data=nil!
}

func main() {
    err := fail()
    if err != nil {
        // 🔥 THIS RUNS! Even though err is logically nil!
        // Because iface.tab is NOT nil!
        fmt.Println("Error is not nil!", err)
    }
}
// ✅ THE FIX: Always return raw unadorned `nil` for error returns:
func safe() error {
    // return nil, NOT a typed pointer!
    return nil
}

Part 3: Struct Embedding (Composition)

Go uses struct embedding rather than class inheritance. Embedded fields and their methods are "promoted" to the outer struct:

type Entity struct {
	ID        string
	CreatedAt time.Time
}

func (e *Entity) Age() time.Duration {
	return time.Since(e.CreatedAt)
}

type User struct {
	Entity   // Embedded: Anonymous field
	Username string
}

func main() {
	u := User{
		Entity:   Entity{ID: "usr_1", CreatedAt: time.Now()},
		Username: "gopher",
	}
	// Direct access to promoted fields & methods
	fmt.Println(u.ID)
	fmt.Println(u.Age())
}

Question: Since Go interfaces are implicit, how do you verify at compile-time that *PostgresStore satisfies the Store interface without allocating memory?

Answer: The Blank Identifier Nil Assertion!

type Store interface {
    Get(id string) ([]byte, error)
    Save(id string, data []byte) error
}

type PostgresStore struct{}
func (p *PostgresStore) Get(id string) ([]byte, error) { return nil, nil }
func (p *PostgresStore) Save(id string, data []byte) error { return nil }

// ✅ COMPILE-TIME ASSERTION:
// If PostgresStore misses any method or has a signature mismatch,
// the Go compiler halts the build here with a clear error!
var _ Store = (*PostgresStore)(nil)

Using (*PostgresStore)(nil) creates a typed nil pointer without allocating any heap memory at runtime.
