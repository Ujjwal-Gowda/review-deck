Measuring a RAG system, so changes are improvements rather than guesses.

Build a golden set first

50–200 real questions (from users, support tickets and docs), each with the expected answer and the IDs of the chunks that contain it. Include tricky ones: questions with no answer in the docs, ambiguous questions, multi-hop questions, and other languages.

StageMetricQuestion it answers
Retrievalrecall@k, MRR, nDCGwas the right chunk retrieved, and how high did it rank?
Generationfaithfulness / groundednessis every claim supported by the retrieved context (no hallucination)?

Operationslatency, cost per query…
  • Measure retrieval separately first: if the right chunk isn't retrieved, no prompt can fix the answer.
  • LLM-as-judge scores faithfulness and correctness at scale (chapter 227). Validate the judge against human labels on a sample.
  • Run the evaluation on every change to chunking, the embedding model, k, the reranker, or the prompt. Tools: Ragas, DeepEval, promptfoo, or a simple script plus a spreadsheet.

214.1 basic Create a 30-question golden set for a document collection you know, with expected source chunks, and compute recall@5 for your current pipeline.

Store the question, answer and chunk IDs in JSON; retrieve; count how often any expected chunk appears in the top 5. That number is your baseline.
