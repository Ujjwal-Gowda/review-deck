Items that don't sit next to each other: each one points to the next. Linked lists teach pointers and references better than anything else, and power queues, LRU caches and allocators.

The picture

Each NODE holds a value and a pointer ("next") to the following node. The list itself only remembers the HEAD. head │ ▼ ┌──────┬───┐ ┌──────┬───┐ ┌──────┬───┐ │ milk │ ●─┼──►│ curd │ ●─┼──►│paneer│ ╳ │ ╳ = None / NULL: the end of the list └──────┴───┘ └──────┴───┘ └──────┴───┘ (address 5000) (address 7300) (address 1200) ← scattered anywhere in memory

An analogy: a treasure hunt. Each clue tells you where the next clue is. Finding clue #50 means following 49 clues, but slipping a new clue into the chain only means rewriting one clue.

A singly linked list, built step by step

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

class LinkedList:
    def __init__(self):
        self.head = None
        self.size = 0

    def push_front(self, value):                 # O(1)
        self.head = Node(value, self.head)       # new node points at the old head
        self.size += 1

    def find(self, value):                       # O(n): walk until found
        cur = self.head
        while cur is not None:
            if cur.value == value:
                return cur
            cur = cur.next
        return None

    def insert_after(self, node, value):         # O(1) once you have the node
        node.next = Node(value, node.next)
        self.size += 1

    def remove(self, value):                     # O(n): find it, then unlink it
        prev, cur = None, self.head
        while cur is not None and cur.value != value:
            prev, cur = cur, cur.next
        if cur is None:
            return False                         # not found
        if prev is None:
            self.head = cur.next                 # removing the head
        else:
            prev.next = cur.next                 # bypass cur
        self.size -= 1
        return True

    def __iter__(self):
        cur = self.head
        while cur:
            yield cur.value
            cur = cur.next

Inserting, drawn out

insert "dahi" after "milk": 1. create the new node, pointing where milk points: [dahi]──► curd 2. point milk at the new node: milk ──► [dahi] ──► curd ──► paneer Only 2 pointers change, however long the list is. That's O(1). The ORDER matters: do step 2 first and you've lost the link to curd forever.

Deleting, drawn out

remove "curd": prev = milk, cur = curd milk ──► curd ──► paneer milk ───────────► paneer (prev.next = cur.next; curd is now unreachable, and garbage-collected / freed)

Reversing a list: the classic exercise

def reverse(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next      # 1. remember the rest of the list
        cur.next = prev     # 2. flip this node's arrow backwards
        prev = cur          # 3. move prev forward
        cur = nxt           # 4. move cur forward
    return prev             # prev is the new head
start: None A → B → C → None after node A: None ← A B → C (prev=A, cur=B) after node B: None ← A ← B C (prev=B, cur=C) after node C: None ← A ← B ← C (prev=C, cur=None) → return C

Finding a cycle: Floyd's tortoise and hare

A buggy list might loop back on itself, and walking it would never end. Move one pointer by 1 step and another by 2. If there's a loop, the fast one laps the slow one and they meet; if not, the fast one reaches the end.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
# The same fast/slow trick finds the MIDDLE of a list: when fast reaches the end, slow is halfway.

When do you actually use one?

Honestly, rarely directly: arrays win for most lists because of the cache (Data Structures). But linked lists are inside things you use all the time: an LRU cache (a hash map plus a doubly linked list), OS task lists, memory allocators' free lists, and hash-table buckets with chaining. They're also an interview favourite, precisely because they test careful pointer handling.

Practice

0.1 basic Implement a doubly linked list with push_back, pop_front and remove(node) in O(1), using one sentinel node that links to itself when the list is empty. Then build an LRU cache (capacity 3) from it plus a dict.

Sentinel: s.prev = s.next = s. Insert x before s (at the back): x.prev, x.next = s.prev, s; s.prev.next = x; s.prev = x. Remove: x.prev.next = x.next; x.next.prev = x.prev. LRU: the dict maps key to node; on get, move the node to the back; on put when over capacity, evict s.next (the least recently used).
