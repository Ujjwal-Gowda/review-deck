2. The DOM Tree & Event Propagation Pipeline

When an event occurs (e.g. clicking a button), the browser dispatches the event in three distinct phases:

  1. Capturing Phase (Trickling down): The event travels from the window object down through document, <html>, <body> to the parent containers until it reaches the target.
  2. Target Phase: The event arrives at the clicked element (the e.target).
  3. Bubbling Phase (Floating up): The event bubbles upward from the target element back to window.
// High-Performance Event Delegation:
// Instead of attaching 1,000 listeners to 1,000 table rows, attach ONE listener to the parent!
const table = document.querySelector("#orders-table");

table.addEventListener("click", (event) => {
  // e.target is the exact clicked element (e.g. a button inside a row)
  const button = event.target.closest("button.action-btn");
  if (!button || !table.contains(button)) return;

  const orderId = button.dataset.orderId;
  console.log("Action clicked for order:", orderId);
});

3. Offloading CPU Work: Dedicated Web Workers

Because the browser UI runs on a single thread alongside JavaScript execution, long-running loops freeze scrolling and user input. Web Workers run scripts in background threads:

// main.js (Main UI Thread)
const worker = new Worker(new URL("./worker.js", import.meta.url), { type: "module" });

// Send large array to worker using zero-copy Transferable ArrayBuffer
const buffer = new Float64Array(1000000);
worker.postMessage({ type: "PROCESS_DATA", buffer }, [buffer.buffer]);

worker.onmessage = (e) => {
  console.log("Computation result from worker:", e.data);
};

// worker.js (Background Thread)
self.onmessage = (e) => {
  if (e.data.type === "PROCESS_DATA") {
    // Heavy math executed without dropping a single frame in the UI!
    const result = heavyCalculation(e.data.buffer);
    self.postMessage(result);
  }
};

4. Browser Storage Comparison

Storage API Capacity Access API Persistence Scope
localStorage ~5MB Synchronous (blocks thread) Persists across sessions until explicitly cleared.
sessionStorage ~5MB Synchronous (blocks thread) Cleared when the browser tab is closed.
IndexedDB Hundreds of MBs / GBs Asynchronous (non-blocking) Structured object store for large datasets and offline apps.
