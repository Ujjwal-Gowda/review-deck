The client side of MCP: how hosts connect to and use servers.

  • Configuration: hosts list their servers (command + arguments for stdio; a URL for HTTP) in a config file (.mcp.json, claude mcp add, a desktop app's settings).
  • Handshake: the client sends initialize with its protocol version and capabilities; the server replies with its own (tools, resources, prompts, logging), and the two sides use what both support.
  • Discovery: tools/list, resources/list and prompts/list. Tool schemas are then given to the model, and tools/call runs when the model chooses a tool.
  • Client capabilities servers can use: sampling (the server asks the host's model to generate text), roots (which folders the server may see), and elicitation (asking the user for input).
  • Writing your own client (in the Python or TS SDK) lets your app use any MCP server. Useful when you build agents (chapter 245).
  • Trust: a server's tool descriptions and results are untrusted input. Only install servers you trust, review the permissions they need, and prefer hosts that ask for approval before tool calls.
