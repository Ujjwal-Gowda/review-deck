Tools turn text generation into real actions, so give them the same safety engineering as any privileged API.

  • Least privilege: the agent's credentials allow only what its tools need: a read-only database role for lookups, scoped API keys, no shell unless it's essential.
  • Classify tools by risk: read-only (free to run) → reversible writes (log them) → irreversible or external actions (payments, sending messages, deleting data) → require human confirmation, showing exactly what will happen.
  • Server-side authorisation: the tool checks that the end user may do this (store, role), whatever the model asked for (chapter 85).
  • Sandboxing: code execution happens in isolated containers or VMs (gVisor, Firecracker, E2B) with no network or secrets, plus CPU, memory and time limits.
  • Tool injection: tool results (web pages, emails, files) can contain instructions. Never let content from one tool silently trigger a high-risk tool; data read from outside must not become commands.
  • Limits: maximum steps, a token or money budget, rate limits per tool, and idempotency keys on writes.
  • Audit: an immutable log of every action, with the user, the conversation and the arguments.

Practice

Treat email content as untrusted data; sending needs human approval showing the recipients and text; rate-limit sends; allow-list recipients; no bulk-send tool at all.
