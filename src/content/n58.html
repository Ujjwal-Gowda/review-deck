The toolkit for answering "why can't A talk to B?"

ip -brief addr              # my IP addresses per interface
ip route                    # default gateway (where packets for "everywhere else" go)
ping -c 3 1.1.1.1           # is the internet reachable at all? (ICMP; may be blocked)
dig +short freshon.in       # DNS: name → IP   (dig freshon.in MX, TXT, @8.8.8.8 to pick a resolver)
tracepath freshon.in        # the hops along the route, and where it stops
ss -ltnp                    # which ports are LISTENING here, and which process owns each
nc -vz api.freshon.in 443   # can I open a TCP connection to this port?
curl -v https://api.freshon.in/health        # full HTTP + TLS conversation
curl -sS -o /dev/null -w '%{http_code} dns=%{time_namelookup} tls=%{time_appconnect} total=%{time_total}\n' URL
sudo tcpdump -i any -n port 631              # see the actual packets (e.g. IPP to a printer)

Debug layer by layer, bottom up

  1. Link / IP: do I have an address? (ip addr) Can I ping the gateway?
  2. Routing: can I ping a public IP? If not, it's the gateway, Wi-Fi or ISP.
  3. DNS: does dig return an IP? If an IP works but the name doesn't, it's DNS.
  4. Port: nc -vz host port. "Refused" means nothing is listening there; a "timeout" means a firewall is dropping the packets.
  5. TLS: curl -v shows certificate errors (expired, wrong name).
  6. Application: the HTTP status and response body.

"Works on localhost but not from my phone" almost always means the server is bound to 127.0.0.1 instead of 0.0.0.0 (check the Local Address column in ss -ltn), or a firewall is in the way.
