Pre-release tests can't prove production works, so keep verifying after you ship.

TechniqueWhat it verifies
Smoke tests after every deploythe app is up, a login works, one key read and write path works; roll back automatically if not
Synthetic monitoringscripted journeys (login → browse → checkout on a test account) every few minutes from outside, which alert before users notice (Checkly, Grafana synthetics, a cron'd Playwright script)
Canary analysisthe new version's error rate and latency compared with the old one's on real traffic, before widening (Deployment Strategies)
Feature-flag rolloutsenable for staff, then 5%, then everyone, watching metrics at each step
Real-user monitoringactual page speed and errors from users' browsers
Chaos experimentsdeliberately kill an instance or slow a dependency, and confirm the system degrades gracefully (Resilience)
Data checksscheduled reconciliations: payments vs orders, stock vs movements, catching silent data bugs

Rules: use dedicated test accounts and tenants, tag synthetic traffic so it's excluded from business metrics, never touch real money or send real SMS, and make every check produce an alert that someone owns.

Practice

0.1 basic Write a Playwright script that checks the FreshOn demo landing page and the POS demo load, and schedule it every 15 minutes with a systemd timer that alerts on failure.

Put the script in check.spec.ts, and make the timer's service run npx playwright test check.spec.ts. On a non-zero exit, send a notification (ntfy.sh, email, or a Telegram bot). That's real synthetic monitoring for free.
