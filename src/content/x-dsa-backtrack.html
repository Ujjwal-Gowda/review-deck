Try a choice, explore from it, undo it, and try the next. The systematic way to search all combinations, with pruning so it stays fast.

The template

def backtrack(path, choices):
    if is_complete(path):
        record(path); return
    for c in choices:
        if not valid(path, c): continue   # PRUNE: skip branches that can't work
        path.append(c)                    # 1. choose
        backtrack(path, next_choices)     # 2. explore
        path.pop()                        # 3. un-choose (restore state for the next option)

Subsets, drawn as a decision tree

items [a, b, c]: at each level decide "take it or skip it" [] take a / \ skip a [a] [] / \ / \ [a,b] [a] [b] [] / \ / \ / \ / \ [a,b,c][a,b][a,c][a] [b,c][b] [c] [] → 2³ = 8 subsets
def subsets(items):
    out = []
    def go(i, path):
        if i == len(items): out.append(path[:]); return
        path.append(items[i]); go(i + 1, path); path.pop()     # take
        go(i + 1, path)                                        # skip
    go(0, []); return out

def permutations(items):
    out, used = [], [False] * len(items)
    def go(path):
        if len(path) == len(items): out.append(path[:]); return
        for i, x in enumerate(items):
            if used[i]: continue
            used[i] = True; path.append(x)
            go(path)
            path.pop(); used[i] = False
    go([]); return out

Pruning makes it practical

Example: choose products whose prices add up to exactly ₹500. Sort the prices first; once the running total exceeds 500, stop exploring that branch entirely, along with every more expensive option after it. Good pruning turns "impossible" into "instant". Classic problems that use it: N-queens, sudoku, word search in a grid, and combination sums.

Costs are exponential by nature: subsets are O(2ⁿ), permutations O(n!). Backtracking is right for small n (under about 20–25) or with heavy pruning. For "count the ways" or "best total" with overlapping subproblems, switch to dynamic programming.
