A backup only counts if you've successfully restored from it.

The 3-2-1 rule

Keep 3 copies of the data, on 2 different kinds of media, with 1 off-site (another region or provider). Add a copy that can't be changed (object lock / WORM storage) so ransomware or a compromised admin account can't delete it.

TypeWhat it is
Fulleverything; simple to restore, large
Incremental / differentialchanges since the last backup / since the last full one
Snapshota point-in-time copy of a disk or volume, fast; still keep a copy outside the same account
Logical (pg_dump)portable SQL; slow for large databases
Physical + WAL (point-in-time recovery)restore to any second, e.g. just before a bad DELETE
restic -r s3:s3.amazonaws.com/freshon-backups init
restic -r … backup /var/lib/app --tag daily            # deduplicated, encrypted, incremental
restic -r … forget --keep-daily 7 --keep-weekly 4 --keep-monthly 12 --prune
restic -r … restore latest --target /tmp/restore-test  # the step everyone skips
  • Back up everything you'd need: databases, uploaded files, configuration, secrets (in encrypted form), and infrastructure code.
  • Automate restore drills: restore to a scratch environment every month, then check that row counts match and the app starts.
  • Encrypt backups, and store the keys separately from the backups.
  • Monitor the last successful backup's age and alert if it's older than a day. A backup job that has quietly failed for 3 months is the classic disaster.
