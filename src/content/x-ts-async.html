Promises and async/await in depth: parallel vs sequential, timeouts, cancellation, and the classic mistakes.

What a promise is

A promise is a placeholder for a value that will arrive later. It's pending until it's fulfilled (with a value) or rejected (with an error). await pauses the async function until it settles, without blocking the thread: other work runs meanwhile (JavaScript).

Sequential vs parallel

// sequential: ~3 × latency. Only when each step needs the previous result
const user = await getUser(id);
const orders = await getOrders(user.id);

// parallel: ~1 × latency. Independent requests
const [prices, stock, promos] = await Promise.all([getPrices(), getStock(), getPromos()]);

// don't await inside a loop for independent work:
for (const id of ids) await refresh(id);                  // slow: one at a time
await Promise.all(ids.map(id => refresh(id)));           // fast: all at once (limit concurrency for big lists)

Timeouts and cancellation

const res = await fetch(url, { signal: AbortSignal.timeout(5_000) });   // throws a TimeoutError after 5 s

const ctrl = new AbortController();
const p = fetch(url, { signal: ctrl.signal });
cancelButton.onclick = () => ctrl.abort();                                // cancel on demand

async function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  let t: ReturnType<typeof setTimeout>;
  const timeout = new Promise<never>((_, rej) => { t = setTimeout(() => rej(new Error("timeout")), ms); });
  try { return await Promise.race([p, timeout]); } finally { clearTimeout(t!); }
}

Classic mistakes

  • Forgetting await: you get a Promise instead of the value, and errors go unhandled. Enable ESLint's no-floating-promises.
  • array.forEach(async …) doesn't wait for anything. Use for…of with await, or Promise.all(array.map(…)).
  • Unbounded parallelism: Promise.all over 10,000 URLs opens 10,000 connections. Use a worker-pool limit (Concurrency Across Languages).
  • Blocking the event loop with CPU work (a big JSON.parse, heavy loops) freezes everything: use worker_threads.

Streams and async iteration

const res = await fetch(url);
for await (const chunk of res.body!) process(chunk);         // stream a large response
async function* pages(url: string) {                          // async generator: paginate lazily
  let next: string | null = url;
  while (next) { const r = await (await fetch(next)).json(); yield* r.items; next = r.next; }
}
for await (const item of pages("/api/orders")) { /* … */ }
