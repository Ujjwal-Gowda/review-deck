Rust's error handling: Result, the ? operator, custom error types, and when panicking is right.

Result and ?

use std::fs;
fn read_qty(path: &str) -> Result<u32, Box<dyn std::error::Error>> {
    let text = fs::read_to_string(path)?;           // on Err: return it immediately (converted via From)
    let qty: u32 = text.trim().parse()?;
    Ok(qty)
}
match read_qty("qty.txt") {
    Ok(q) => println!("{q}"),
    Err(e) => eprintln!("failed: {e}"),
}

Libraries: precise error types with thiserror

#[derive(Debug, thiserror::Error)]
pub enum StockError {
    #[error("unknown sku {0}")]
    UnknownSku(String),
    #[error("{sku}: wanted {wanted}, have {have}")]
    Insufficient { sku: String, wanted: u32, have: u32 },
    #[error("reading stock file")]
    Io(#[from] std::io::Error),                     // enables ? on io errors inside this library
}
pub fn reserve(stock: &mut HashMap<String, u32>, sku: &str, n: u32) -> Result<(), StockError> {
    let have = stock.get_mut(sku).ok_or_else(|| StockError::UnknownSku(sku.into()))?;
    if *have < n { return Err(StockError::Insufficient { sku: sku.into(), wanted: n, have: *have }); }
    *have -= n; Ok(())
}
// callers can match on the variant:  Err(StockError::Insufficient { have, .. }) => suggest(have)

Applications: convenient errors with anyhow

use anyhow::{Context, Result, bail};
fn main() -> Result<()> {
    let cfg = fs::read_to_string("config.toml").context("reading config.toml")?;   // adds a context line
    let port: u16 = cfg.parse().with_context(|| format!("bad port {cfg:?}"))?;
    if port < 1024 { bail!("port {port} needs root"); }
    Ok(())
}
// on failure it prints the chain: "Error: bad port "x"\n\nCaused by: invalid digit found in string"

Option ↔ Result, and handy combinators

opt.ok_or(MyErr::Missing)?            // Option → Result
res.ok()                               // Result → Option (drops the error)
res.map_err(|e| MyErr::Parse(e.to_string()))?
res.unwrap_or_default(); res.unwrap_or_else(|_| fallback())
let v: Result<Vec<_>, _> = iter.map(parse).collect();   // all-or-nothing

When to panic

  • panic!, unwrap(), expect() are for bugs and impossible states, and fine in tests and quick prototypes.
  • In library code, return Result. Prefer expect("reason this can't fail") over a bare unwrap() when you're sure.
  • Indexing (v[i]), integer overflow (debug builds) and division by zero panic; use .get(i) and checked_* when inputs are external.
