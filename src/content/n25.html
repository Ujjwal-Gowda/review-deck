Writing code once for many types in each of your languages, and knowing what it costs.

Chapter 24 introduced generics as part of type systems. Here's how to use them well in practice.

The same generic function, four times

function groupBy<T, K extends PropertyKey>(xs: T[], key: (x: T) => K): Record<K, T[]> {
  const out = {} as Record<K, T[]>;
  for (const x of xs) (out[key(x)] ??= []).push(x);
  return out;
}
func GroupBy[T any, K comparable](xs []T, key func(T) K) map[K][]T {
    out := make(map[K][]T)
    for _, x := range xs { out[key(x)] = append(out[key(x)], x) }
    return out
}
use std::{collections::HashMap, hash::Hash};
fn group_by<T, K: Eq + Hash>(xs: Vec<T>, key: impl Fn(&T) -> K) -> HashMap<K, Vec<T>> {
    let mut out: HashMap<K, Vec<T>> = HashMap::new();
    for x in xs { out.entry(key(&x)).or_default().push(x); }
    out
}
from collections import defaultdict
from typing import Callable, Hashable
def group_by[T, K: Hashable](xs: list[T], key: Callable[[T], K]) -> dict[K, list[T]]:
    out: dict[K, list[T]] = defaultdict(list)
    for x in xs: out[key(x)].append(x)
    return dict(out)

Generic types

type Stack[T any] struct{ items []T }
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
    var zero T
    if len(s.items) == 0 { return zero, false }
    v := s.items[len(s.items)-1]
    s.items = s.items[:len(s.items)-1]
    return v, true
}

Static vs dynamic dispatch

fn total_static(xs: &[impl Shape]) -> f64 { xs.iter().map(|s| s.area()).sum() }   // monomorphised: one copy per type, inlinable
fn total_dyn(xs: &[Box<dyn Shape>]) -> f64 { xs.iter().map(|s| s.area()).sum() }  // vtable: mixed types, one copy, indirect call
Trade-offs

Generics / static dispatch: type-safe, fastest, but bigger binaries and slower compiles (Rust/C++), and all elements must share one type. Interfaces / dynamic dispatch: mixed types in one collection, smaller code, a tiny cost per call. Over-generic code is a smell: write the concrete version first, and generalise when a second real use appears.

fn largest<T: PartialOrd>(xs: &[T]) -> Option<&T> {
    let mut it = xs.iter();
    let mut best = it.next()?;
    for x in it { if x > best { best = x; } }
    Some(best)
