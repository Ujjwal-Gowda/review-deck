Lifting state and prop drilling

When two siblings need the same state, move it up to their parent and pass it down. If you're passing it through five layers that don't use it, reach for Context (or composition: pass components as children).

Reducers for state with rules

type Action = { type: "add"; item: Item } | { type: "remove"; sku: string } | { type: "clear" };
function cart(state: Item[], a: Action): Item[] {
  switch (a.type) {
    case "add":    return [...state, a.item];
    case "remove": return state.filter(i => i.sku !== a.sku);
    case "clear":  return [];
  }
}
const [items, dispatch] = useReducer(cart, []);
dispatch({ type: "add", item });    // every change is a named, testable event

A reducer is a pure function, so it's trivially unit-testable, and it's the same idea as the state machines in chapter 36.

Rules of thumb

Keep state as local as possible. Store the minimum and derive the rest. One source of truth per fact. Server data is a cache, so treat it as one.
