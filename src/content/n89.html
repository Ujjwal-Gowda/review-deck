Receiving events from other services (payments, shipping, GitHub) reliably and securely.

A webhook is the provider calling your URL when something happens: "payment captured", "delivery completed". It's the reverse of polling.

app.post("/webhooks/razorpay", express.raw({ type: "application/json" }), async (req, res) => {
  // 1. VERIFY the signature over the RAW body (a parsed-then-reserialised body won't match)
  const expected = crypto.createHmac("sha256", process.env.RZP_WEBHOOK_SECRET!).update(req.body).digest("hex");
  const got = req.header("X-Razorpay-Signature") ?? "";
  if (got.length !== expected.length || !crypto.timingSafeEqual(Buffer.from(got), Buffer.from(expected)))
    return res.sendStatus(401);
  const event = JSON.parse(req.body.toString());
  // 2. DEDUPLICATE: providers retry, so the same event can arrive twice
  if (await db.webhookEvents.exists(event.id)) return res.sendStatus(200);
  // 3. STORE + ENQUEUE, then answer fast (providers time out after a few seconds)
  await db.webhookEvents.insert({ id: event.id, type: event.event, payload: event });
  await queue.add("process-payment-event", { id: event.id });
  res.sendStatus(200);
});

Rules

  • Verify signatures (HMAC with a shared secret), and check the timestamp to reject replays.
  • Idempotent processing: delivery is at-least-once, and events can arrive out of order. Re-fetch the current state from the provider's API when order matters.
  • Respond 2xx quickly and do the work in a background job (chapter 91).
  • Develop locally with a tunnel: ngrok http 8080, cloudflared, or the provider's CLI forwarder.
  • If you send webhooks: sign them, retry with backoff, give each event an ID, and let customers see delivery logs.
Security lens · Webhooks

Verify signatures over the raw body, check timestamps against replay, and never let a webhook URL you configure point at internal addresses (SSRF).

Practice

89.1 think A webhook for the same payment arrives twice, and the "captured" event arrives before "authorized". How should your handler cope?

Deduplicate by event ID; make processing idempotent; don't rely on the arrival order. Fetch the payment's current state from the provider's API, or apply state transitions only when they move forward.
