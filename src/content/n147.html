Describing cloud infrastructure as code: reviewable, repeatable and reversible.

# main.tf
terraform {
  required_providers { aws = { source = "hashicorp/aws", version = "~> 5.0" } }
  backend "s3" { bucket = "freshon-tfstate", key = "prod/terraform.tfstate", region = "ap-south-1", use_lockfile = true }
}
provider "aws" { region = var.region }
variable "region" { default = "ap-south-1" }

resource "aws_s3_bucket" "invoices" { bucket = "freshon-invoices-prod" }
resource "aws_s3_bucket_public_access_block" "invoices" {
  bucket = aws_s3_bucket.invoices.id                     # a reference creates a dependency (the graph)
  block_public_acls = true; block_public_policy = true; ignore_public_acls = true; restrict_public_buckets = true
}
module "vpc" { source = "terraform-aws-modules/vpc/aws"; version = "~> 5.0"; cidr = "10.0.0.0/16" }
output "bucket" { value = aws_s3_bucket.invoices.bucket }
terraform init       # download providers, configure the state backend
terraform plan       # DIFF: what would change (+ create, ~ update, - destroy). Read it every time.
terraform apply      # make it so
terraform destroy    # tear it all down (careful)

State

Terraform records what it created in a state file, mapping config to real resource IDs. Keep it in a remote backend (S3, Terraform Cloud) with locking, so two applies can't collide. It contains secrets, so restrict access. Drift (someone clicked in the console) shows up in the next plan. terraform import adopts existing resources.

Alternatives: OpenTofu (the open-source fork), Pulumi (real programming languages), AWS CDK, CloudFormation, Crossplane (Kubernetes-native).

Practice

147.1 basic Write Terraform that creates a private bucket with public access blocked. Run plan, apply, change a tag, plan again, then destroy.

The second plan shows a single in-place change (~) for the tag. That's declarative diffing. Keep state remote once more than one person applies.
