Allocation, garbage collection, and memory layout as performance levers.

  • Allocation is not free: heap allocation plus GC work often dominates in Go, Java and JS services. Reduce it with preallocated slices (make([]T, 0, n)), reused buffers (sync.Pool), avoiding needless string concatenation, and streaming instead of loading whole files.
  • GC trade-offs: throughput vs pause time vs memory headroom. Go: GOGC (higher means less GC and more memory) and GOMEMLIMIT (a soft cap, good in containers). Node: --max-old-space-size. JVM: G1 or ZGC.
  • Escape analysis (Go, JVM) keeps short-lived values on the stack. go build -gcflags=-m shows what escapes to the heap.
  • Rust and C: no GC, but allocation still costs. Use arenas and small-vector optimisations in hot paths.
  • Python: every object carries overhead. For big numeric data use NumPy/arrays; __slots__ for millions of small objects; generators instead of lists.
  • Leaks in GC languages are references kept by accident: global caches, listeners, closures. Compare two heap snapshots to find what keeps growing.
