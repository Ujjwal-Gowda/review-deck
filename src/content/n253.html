A plan for becoming a regular open-source contributor. The mechanics are in chapter 50.

  1. Month 1: user to reporter. File high-quality bug reports (minimal reproduction, versions, expected vs actual) for tools you use. Answer a few questions in issues or discussions.
  2. Month 2: docs and tests. Fix confusing docs you tripped over; add missing tests; improve error messages.
  3. Month 3: small fixes. Take good first issue bugs; comment first; keep the PR small; respond to review quickly.
  4. Ongoing: depth over breadth. Pick 1–2 projects and learn their architecture. Regular contributors get trusted with bigger work (and reviewer or maintainer rights).

Being a maintainer (even of your own small project)

  • A README with a clear purpose, a LICENSE, CONTRIBUTING, issue and PR templates, CI, and semver releases with a changelog.
  • Label issues, respond kindly, say no to scope creep, and automate the repetitive parts (Dependabot, release workflows).
  • Your own tools (the printer doctor, the MCP server from Project 10) are good candidates to open-source.
