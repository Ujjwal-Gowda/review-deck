"Fearless concurrency": threads, message passing and shared state, where the compiler prevents data races, plus async with tokio for I/O.

Threads

use std::thread;
let orders = vec![1, 2, 3];
let handle = thread::spawn(move || {          // move: the thread takes ownership of what it uses
    orders.iter().sum::<i32>()
});
let total = handle.join().unwrap();           // join returns the thread's result

thread::scope(|s| {                           // scoped threads may BORROW local data
    for chunk in data.chunks(1000) { s.spawn(move || process(chunk)); }
});                                           // all joined automatically here

Message passing

use std::sync::mpsc;
let (tx, rx) = mpsc::channel();
for id in 0..4 {
    let tx = tx.clone();
    thread::spawn(move || { tx.send((id, work(id))).unwrap(); });
}
drop(tx);                                      // close our copy so the loop below can end
for (id, result) in rx { println!("{id}: {result}"); }

Shared state: Arc + Mutex

use std::sync::{Arc, Mutex};
let stock = Arc::new(Mutex::new(HashMap::from([("milk".to_string(), 10u32)])));
let handles: Vec<_> = (0..5).map(|_| {
    let stock = Arc::clone(&stock);            // Arc: shared ownership across threads (atomic refcount)
    thread::spawn(move || {
        let mut s = stock.lock().unwrap();     // the guard unlocks when dropped
        if let Some(q) = s.get_mut("milk") { if *q > 0 { *q -= 1; } }
    })
}).collect();
for h in handles { h.join().unwrap(); }

Send (safe to move to another thread) and Sync (safe to share references across threads) are traits the compiler checks automatically. Rc isn't Send, so using it across threads is a compile error: data races are caught before running.

Data parallelism with rayon

use rayon::prelude::*;
let total: u64 = lines.par_iter().map(|l| parse_amount(l)).sum();   // iter → par_iter: all cores

Async with tokio (I/O-heavy work)

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = reqwest::Client::new();
    let urls = vec!["https://example.com/a", "https://example.com/b"];
    let tasks: Vec<_> = urls.into_iter().map(|u| {
        let c = client.clone();
        tokio::spawn(async move { c.get(u).send().await.map(|r| r.status()) })
    }).collect();
    for t in tasks { println!("{:?}", t.await?); }
    tokio::time::timeout(Duration::from_secs(5), slow_call()).await??;   // timeouts
    Ok(())
}

Choose threads or rayon for CPU work, and tokio async for many concurrent network operations. Don't block inside async code (use tokio::task::spawn_blocking).

Practice

0.1 basic Count words across 20 text files in parallel: first with threads + mpsc (one thread per file), then with rayon par_iter. Merge the HashMaps at the end and compare the code size.

With rayon: files.par_iter().map(|f| count(f)).reduce(HashMap::new, merge), a few lines, and the compiler guarantees there are no races. The threads version needs a clone of tx per thread, drop(tx), and a merge loop.
