How containers reach each other and the outside world.

docker network create shop
docker run -d --name db  --network shop -e POSTGRES_PASSWORD=dev postgres:17
docker run -d --name api --network shop -p 8080:8080 -e DATABASE_URL=postgres://postgres:dev@db:5432/postgres shop-api
#   inside the network: the api reaches Postgres at hostname "db" (Docker's built-in DNS) on port 5432
#   from the host: only the api is published → http://localhost:8080  (Postgres isn't exposed at all)
docker network inspect shop
ConceptMeaning
bridge networka private virtual LAN for containers (user-defined bridges give DNS by container name)
-p 8080:80publish: host port 8080 → container port 80. -p 127.0.0.1:5432:5432 binds to localhost only.
EXPOSEdocumentation only; it doesn't publish anything
host networkshares the host's network stack (no isolation, no port mapping; Linux only)
host.docker.internalreach a service on the host from a container
Classic mistakes

localhost inside a container means the container itself, not your laptop and not another container: use the service name. An app listening on 127.0.0.1 inside the container can't be reached via -p; it must listen on 0.0.0.0. And Docker's published ports bypass UFW firewall rules on Linux, so bind databases to 127.0.0.1 or don't publish them.

Inside the API container, localhost means the API container itself. Docker's DNS resolves db to the Postgres container's IP.
