Testing critical user journeys in a real browser, without building a flaky test suite.

// tests/checkout.spec.ts   run: npx playwright test   (debug: --ui, --headed, trace viewer)
import { test, expect } from "@playwright/test";
test("customer can place an order", async ({ page }) => {
  await page.goto("/");
  await page.getByRole("button", { name: "Add Paneer 200g" }).click();     // role-based locators: resilient
  await page.getByRole("link", { name: /cart/i }).click();
  await page.getByLabel("Mobile").fill("9876543210");
  await page.getByRole("button", { name: "Place order" }).click();
  await expect(page.getByText(/Order #\d+ confirmed/)).toBeVisible();      // auto-waits and retries
});

Avoiding flakiness

  • Never sleep(2000): use auto-waiting assertions (expect(…).toBeVisible()).
  • Locate by role, label or test ID, not by CSS classes or DOM structure.
  • Each test creates its own data (via the API, or seeded fixtures) and doesn't depend on test order.
  • Mock unstable third parties (page.route("**/razorpay/**", …)) but keep your own backend real.
  • On failure, save a trace, screenshot and video (Playwright does this with trace: "on-first-retry").

Scope: E2E tests are slow and costly, so cover only the money paths (sign-up, checkout, payment, the core admin action). Five solid E2E tests beat 200 flaky ones. Playwright also does visual comparisons, API testing, and mobile viewport emulation.
